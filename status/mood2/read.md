## Що віддати

Тільки JSON-масив, без пояснень до і після, без ``` — масив і все. Кожна позиція:

```
{
  "id": "p1",
  "kind": "moon_sign | moon_house | void | ingress | window | span | natal",
  "from": "HH:MM" або null,
  "to": "HH:MM" або null,
  "weight": 0..5,
  "bodies": "яка планета діє, своїми словами з тексту",
  "house": "N" або null,
  "formula": "рівно те, що в дужках, символ за символом",
  "meaning": "його трактування, повністю, без скорочень",
  "natal": "Меркурій(-)" або null,
  "flag": "▲" або "▼" або "",
  "span": "по 2026-11-26" або null
}
```

Правила, кожне з яких перевіряється потім арифметично:

- **`id`** — `p1`, `p2`, … у тому ж порядку, в якому позиції йдуть у тексті.
- **`kind`** — `moon_sign` для рядка «Луна в N° знака …», `moon_house` для «Луна в N доме»,
  `void` для «Холостая Луна», `ingress` для «Луна переходит в знак», `window` для вікна з
  годинами «с HH:MM до HH:MM» або моменту «в HH:MM», `span` для багатоденного «В период с … по
  …», `natal` — **окрема позиція** на кожен рядок «на моє/мій/мою <планету>(+/-)» з його
  довгим трактуванням у `meaning`.
- **`weight`** — скільки знаків `✤` стоїть перед «Влияет». Немає жодного — нуль.
- **`formula`** — вміст дужок наприкінці, скопійований символ за символом: `(☽5°♐☍♅5°♊)`.
  Немає дужок — порожній рядок.
- **`meaning`** — його текст, не твій переказ. Не скорочуй і не пом'якшуй.
- **`natal`** — ім'я планети власника і знак у дужках, як у тексті: `Меркурій(-)`,
  `Сонце(+)`. Переклади назву планети українською, решту лиши як є.
- **`flag`** — трикутник після двокрапки: `▲` або `▼`. Немає — порожній рядок. Це його власна
  позначка, добра чи погана це річ; не вирішуй за нього.
- Позиція `natal` належить тому вікну, під яким вона стоїть: постав її `from`/`to` такими
  самими, як у того вікна, а `span` — якщо трактування саме каже, що транзит довгий. Порядок
  важливий: натальна позиція має йти в масиві **відразу за своїм вікном**.
- Два натальні рядки можуть мати одне спільне трактування — тоді `meaning` того, під яким воно
  надруковане, несе текст, а в іншого `meaning` порожній. Не дублюй абзац і не вигадуй другий.

Якщо чогось у тексті немає — null або нуль. Не додавай позицій, яких у тексті немає, навіть
якщо «так було б логічніше».
