# t1067 — panel: sys.path grows on every /changes request

Fix from the phase-2 review (`status/state/code-review/2026-10-31-panel-phase2-scan.md`, M6).

## Problem / goal

`changes_html()` runs `sys.path.insert(0, HOME / "tasks")` unconditionally on every
request, in a service that runs 24/7. Each page load leaks one path entry forever, and
`tasks/` sits permanently at the *front* of the import path, ahead of `panel/` — one
future module-name collision away from shadowing a panel import.

## Test cases

- **TC1 (regression)** — rendering `/changes` twice leaves `sys.path` the same length as
  rendering it once; the tasks path appears in it at most once. Fails before (each call
  adds an entry).

## Approach

Insert the path only if it is not already present, and append it to the back rather than
the front — the task-title import is a nicety and must not outrank the panel's own
modules. The graceful degrade (titles lost, page alive, when `store.py` breaks) stays.
