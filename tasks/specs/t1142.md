# t1142 — the nightly review is killed before it writes a report

## Problem / goal

`noos-codereview.service` has produced no report since 2026-11-02. It starts at 05:15 every
morning and twelve minutes later the journal says:

```
code-review-headless.sh[79805]: Background tasks still running after 600s; terminating.
Set CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0 to wait indefinitely.
systemd[1469]: Finished Noos: nightly self code-review ...
```

The review prompt runs an **ultracode** multi-agent review, and a `Workflow` runs in the
background of the headless session. `claude -p` waits for background tasks only up to its
print-mode ceiling — 600 s by default — then terminates them and exits. The review is still
fanning out at that point, so the scan report is never written, no fix is ever made, and no
Telegram summary is sent.

Two defects, one cause:

1. **The ceiling is too low for this run** and the script never raises it. Eight consecutive
   nights (3–10 November) died at the same 600 s mark.
2. **The failure is invisible.** The script ends in `exec claude`, so the service inherits
   the exit code of a session that exited cleanly after killing its own work. systemd logs
   `Finished` with `status=0/SUCCESS`, the unit looks healthy in `systemctl`, and eight
   missing reports went unnoticed. A run that produces no scan report must fail loudly.

## Test cases

- **TC1 —** the script exports `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` before invoking
  `claude`, so background review agents are waited for instead of killed (regression: the
  current script sets nothing and the default 600 s applies).
- **TC2 —** the script does not hand the process over with `exec claude`, because the
  post-run check has to execute after the session exits.
- **TC3 —** run end to end with a stubbed `claude` that writes `<today>-scan.md`: the script
  exits 0 and sends no warning.
- **TC4 —** run with a stubbed `claude` that writes nothing: the script exits non-zero (so
  the unit shows `failed`) and sends exactly one Telegram warning.
- **TC5 —** that warning goes out with `--quiet`, because it arrives around five in the
  morning.
- **TC6 — edge:** a stale report from an earlier day does not satisfy the check — only a
  report dated today counts, otherwise the first broken night would be the last one noticed.

## Approach

Two lines of shell. `export CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` lifts the ceiling; the
run stays bounded by the unit's own `TimeoutStartSec=3600`, so an actually hung workflow is
still killed at 06:15 — now with a `failed` state instead of a silent success. `exec` becomes
a plain call, and after it the script checks for today's scan report, warns quietly and exits
non-zero when it is missing.

Tests drive the real script in a temporary `HOME` with stubs for `claude`, `notify.sh` and
the venv python, so nothing touches the network, Telegram or the live state directory.

Deliberately out of scope: the review prompt itself, the size of the fan-out (the prompt
already caps it at about eight agents), and the unit file — the fix belongs in the script,
which is in the repository, rather than in `~/.config/systemd/user`, which is not. Also out
of scope: the second broken timer found the same evening, `noos-mood-ask.timer`, stopped on
1 November — a separate task.
