# t1075 — defer must understand period phrases

Found by the phase-6 review (04c09b7, finding M1 in
`status/state/code-review/2026-10-31-panel-phase6-scan.md`).

## Problem

The task board's «вихідні» button sends `store.py defer <id> "на вихідних"`, but `defer`
parses the phrase with `parse_due()` only — the weekend (and week, and month) wordings live
in `parse_period()`. So the button fails on every press with «не зрозумів дату», and the
same wording is refused when a defer comes from Telegram. (This very task demonstrated the
sibling behavior: `add` *does* parse periods, and ate the «вихідні» out of the task title.)

## Fix

`defer` parses the phrase the same way `add` does: `parse_period()` first, then
`parse_due()` on the remainder. A parsed period is written into the defer event and
replayed by `state()`; a parsed date behaves as before. A phrase neither parser understands
is still refused without touching the log (the t1048 guard stays).

Moving a task to a period deliberately clears its hard date (the event carries
`due: null`), mirroring how the columns treat a date as the stronger claim. Old defer
events carry no `period` key and replay exactly as before.

## Test cases

- **TC1** — `defer t001 "на вихідних"` succeeds: the task gets the weekend period, its due
  is cleared, and the log line carries both. (Fails before the fix: SystemExit.)
- **TC2** — `defer t001 "завтра"` still sets a date and leaves any period untouched.
- **TC3** — an unparseable phrase still refuses and keeps the existing due (t1048).
- **TC4** — a defer event without a `period` key replays without touching the task's
  period (old logs unchanged).
