# t1100 — panel: phase 11, authentication

The owner's instruction, 2026-11-01: «роби вже автентифікацію». Design in `t1099.md` and
`docs/features/ADMIN-PANEL.md` § Phase 11.

## Problem / goal

The panel serves everything it knows to anyone who can reach `0.0.0.0:8091` — the whole home
network, no credential. Phase 8's review demonstrated what that means in practice (t1094),
and phases 9 and 10 both wait on the panel being able to tell who is asking.

## What this builds

- `panel/auth.py` — `hash_password()` / `check_password()` over `hashlib.scrypt` with a
  random salt (stdlib, no dependency), the record stored as
  `scrypt$n$r$p$salt_hex$hash_hex`; a `set` / `clear` / `show` CLI that reads the password
  from a terminal prompt and never echoes, logs or prints it.
- `.env.panel` (mode 600, git-ignored) holds the record and nothing else.
- Session tokens in memory: 32 random bytes, expiry `panel.auth.ttl_hours` (12), compared
  with `hmac.compare_digest`. A restart logs out.
- Cookie `noos_panel`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Max-Age` matching the TTL.
- Rate limiting per source address: `panel.auth.max_attempts` (5) failures then a lock for
  `panel.auth.lock_min` (5). Every attempt — success, failure, lockout — appended to
  `status/state/panel-auth.jsonl`.
- Every path requires a session except `/login` and `/static/*`. An unauthenticated GET
  redirects to `/login`; an unauthenticated POST is refused 403 and never acted upon.
- **Fails closed:** with no password configured the panel serves only the login page, which
  says the one command that sets one. "Unconfigured" never means "open".
- `/logout` drops the session.

## Deliberately not done here

- **`panel.host` stays `0.0.0.0`.** The design said narrow the bind to the tailnet; the
  tailnet has exactly two devices — this machine and his phone — and the machine he actually
  works from is on the Wi-Fi, not on it. Narrowing would lock him out of his own panel, which
  is this phase's real risk. The setting is one word (`panel.host: "tailscale"`) the day
  Tailscale is installed on that machine; with a password in front, the LAN bind is no longer
  the open door it was.
- TLS. On plain HTTP the password crosses the Wi-Fi inside the WPA2 link and in clear on the
  wire of each device. Named in the docs; `tailscale cert` is the upgrade.

## Test cases

- **TC1 —** the right password verifies, a wrong one does not, and the record contains
  neither the password nor anything reversible to it.
- **TC2 —** a tampered or malformed record verifies nothing instead of raising.
- **TC3 —** two hashes of the same password differ (random salt).
- **TC4 —** a fresh session is valid; one past its expiry is not; an unknown token is not.
- **TC5 —** five failures from one address lock it, and the right password is refused while
  locked; another address is unaffected; the lock expires.
- **TC6 —** every attempt is appended to the log, with the outcome, and the log never
  contains the password attempted.
- **TC7 —** with no password configured, `authenticated()` is false for every request and
  the login page names the command that sets one.
- **TC8 —** `/static/panel.css` and `/login` need no session; every other path does; an
  unauthenticated POST is refused without reaching any action.
- **TC9 —** the cookie carries `HttpOnly`, `SameSite=Strict` and `Path=/`.
- **TC10 —** `auth.py set` writes mode 600, and `clear` removes the record.
