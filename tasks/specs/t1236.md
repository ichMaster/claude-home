# t1236 — the services «docker не відповідає» warn can never fire

## Problem / goal

services.sh (t1208) emits `severity: warn`, «docker не відповідає», `value.docker:
false` when the docker daemon dies. But watch.py's signature for the `services` probe
serialises only (tmux, claude_home, memory_timer, exited) — the docker-dead value
produces a byte-identical signature to the healthy state, so `changed` stays False and
the change-only warn is never delivered, and neither is the recovery. The alert the
t1208 fix was written to surface is unreachable: a dead docker daemon stays invisible
to the watcher indefinitely. (Reproduced: both states returned
`{"tmux": true, "claude_home": true, "memory_timer": true, "exited": ""}`.)

## Test cases

- **TC1 — regression:** a healthy services value and the exact docker-dead value
  services.sh produces yield different signatures. Fails before the change.
- **TC2 —** two identical docker-dead values keep the same signature (no re-alert
  every 15 minutes).
- **TC3 — edge:** a container-count change alone still does not change the signature
  (the count is deliberately not alert-worthy).

## Approach

Add `docker` to the key tuple in `signature()` for the services probe. With it, every
input of the probe's `bad` list (and therefore its severity) is part of the signature.
