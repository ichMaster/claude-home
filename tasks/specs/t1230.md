# t1230 — final_reading reads the v2 log: learn and calibrate went blind at the cutover

## Problem / goal

Since the v2 cutover (2026-11-12) the delivered morning reading is written by
`mood2.log_run()` to `status/state/astro2/mood-v2.log`, while v1's
`status/state/mood.log` receives only biorhythm blocks. But the one shared log chain —
`mood.final_reading()` — still parses only v1's log, so its two consumers are silently
dead for every day since the cutover:

- `astro_learn.py learn` gets «нашого читання за цей день немає» although a reading was
  sent — the РОЗХОДЖЕННЯ comparison is skipped and the model is handed a false premise;
- `mood_feedback.py calibrate` prints «немає прогнозу» and records no rule despite
  recorded /feel remarks and a delivered reading.

Only inbox.py's recalc was migrated (t1214). This is t1127 again: the chain is shared,
so the fix belongs in `final_reading` itself.

## Test cases

- **TC1 —** given a v1 log holding only «біоритми» for a day and a v2 log holding a
  full read/pick/wide/day block for the same day, `final_reading` returns the v2 «day»
  section (regression; returns "" before the fix).
- **TC2 —** a pre-cutover day that lives only in the v1 log still returns the v1
  reading (legacy days stay readable).
- **TC3 — edge:** two v2 blocks for one day (a recalc) — the newest block wins, same
  recency-per-block rule as v1 (t1148).

## Approach

Extract the block scan into `_final_from(log, day, names)`; `final_reading` consults
`v2_log_path()` first — the astro2 log, None when v2 is unconfigured or a named subject
is being read (v2 reads the owner only) — with the final v2 stage name
(`astro2.stages[-1]`), then falls back to v1 with `_FINAL_SECTIONS` unchanged. Both
consumers already go through this chain, so nothing else changes.
