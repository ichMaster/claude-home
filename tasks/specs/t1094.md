# t1094 — panel: the journal pane published the owner's calendar on an unauthenticated port

Found by the phase-8 review (8c700a3, finding H1 in
`status/state/code-review/2026-11-01-panel-phase8-scan.md`).

## Problem

`panel/server.py::journal_text` ran `journalctl --user -u <unit> -n 40` and rendered
everything it returned. For a headless unit that output **is the content the model
composed**: the digest's calendar block, mail subjects, task titles; for
`noos-codereview.service` it is the nightly security review's own prose, i.e. the list of
findings this repository has not fixed yet.

`panel.host` is `0.0.0.0` — the owner's deliberate choice (2026-10-31) — so this was served
with HTTP 200 to any device on the home Wi-Fi with no credential. Demonstrated in the review
from the LAN address: a calendar line naming two private appointments.

The sharp part is the inconsistency: the settings table on the **same page** refuses to print
`user.name` and `tasks.calendar.id` precisely because the port is open, and the journal pane
beside it printed the calendar's contents. A door locked beside an open window.

## Fix

The journal pane shows **systemd's own lines only** — `journalctl … -t systemd` — which is
where the diagnostic lives: `Starting`, `Finished`, `Failed with result …`,
`Main process exited, code=exited, status=1`, the CPU time. A unit's own stdout is withheld
and the pane says so, naming the terminal command that shows it.

`panel.journal_scope` (`systemd` | `full`) carries the decision in config, so the full
journal can be re-enabled the day the panel has authentication — phase 10 — rather than
requiring a code change. Priority filtering was measured and rejected: systemd logs a
script's stdout at the same priority 6 as its own lines, so only the identifier separates
them.

## Test cases

- **TC1 —** with the default scope, the `journalctl` command carries `-t systemd`.
  (Fails before the fix: no identifier filter is passed.)
- **TC2 —** with `panel.journal_scope = "full"`, the identifier filter is absent — the
  switch is real, not decoration.
- **TC3 —** the rendered pane states that the unit's own output is withheld and names
  `journalctl --user -u <unit>`; with `full` it does not.
- **TC4 —** the allowlist behaviour from t1090 is unchanged: an unknown unit still reaches
  no command.

## Approach

`journal_text` reads `panel.journal_scope`; `render_rules` takes the note as a flag so the
renderer stays pure. No change to the allowlist, which the review verified holds.

Deliberately not done: removing the pane (the exit code and the failure line are the answer
to «чому дайджест мовчав» in every case where the unit actually failed), and changing
`panel.host` — that is the owner's call, and it is recorded as his.
