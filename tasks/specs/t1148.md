# t1148 — mood: final_reading returns a stale resumed text after a newer full run

## Problem / goal

`final_reading()` in `status/mood.py` walks `_FINAL_SECTIONS` by NAME priority
(«письмо (перероблено)» first) over `logged_sections()`, which collapses all of a day's
blocks into one dict and loses cross-name recency. The sequence morning full run (logs
«письмо») → `--resume` (logs «письмо (перероблено)») → a second full run (the panel's
«Перерахунок» button; logs a new «письмо» and sends that text) makes `final_reading()`
return the superseded resumed text instead of what was actually sent last.

The consequence is silent and feeds the append-only calibration store wrong data:
`mood_feedback.calibrate()` compares the owner's evening remarks against a reading he never
received last (while the 21:00 question is built from the recalc's claims, since
`save_claims` replaces the day's set), and `astro_learn`'s РОЗХОДЖЕННЯ compares the
reference against the wrong reading — both can write wrong ПРАВИЛО lines.

`yesterday_block()` already has the correct semantics: walk blocks newest-first, take the
first block holding any final section. Found by the nightly code review of 2026-11-11 (M3).

## Test cases

- **TC1 (regression) —** given a day's log with a full run, then a resumed block, then a
  second full run, `final_reading()` returns the second full run's text. Fails before the
  change (returns the resumed text), passes after.
- **TC2 —** full run followed by `--resume` only: the resumed text still wins (the existing
  `test_final_reading_prefers_the_resumed_text` guards this).
- **TC3 — edge:** a trailing `--only bio` block (holding only «біоритми») is skipped and
  the newest block with a final section wins (covered by TC1's shape: the scan continues
  past blocks without final sections).

## Approach

Rewrite `final_reading()` to walk the day's blocks newest-first (same scan as
`logged_sections`), and inside each block check `_FINAL_SECTIONS` in priority order — a
full-run block holds «письмо», a resume block holds only «письмо (перероблено)», so the
within-block priority is harmless and keeps legacy days readable. `logged_sections()`
itself is untouched (`--resume` needs its cross-block merge to find «вибір»).
