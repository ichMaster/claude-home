# t1162 — inbox loses a document sent with a caption

## Problem / goal

`handle_update` takes `text = (msg.get("text") or msg.get("caption") or "").strip()` and
reads an attached document only `if not text`. A document with a caption — exactly how the
owner forwards the astrologer's week as a `.txt` with «це на завтра» on it — never reaches
`read_document`: the classifier sees three words of caption, the reference body is silently
discarded, and nothing is parked or stored. This is the t1054/t1059 data loss again, through
the caption door.

Found by the nightly code review, 2026-11-12 (scan report, Medium #5).

## Test cases

- **TC1 —** given an update carrying a document AND a caption, when `handle_update` runs,
  then the classifier sees the document body (with the caption above it), not the caption
  alone (regression: fails before the fix).
- **TC2 —** a document without a caption is still read (the t1054 path keeps working).
- **TC3 —** a plain text message never triggers a document download.

## Approach

Read the document whenever one is attached, regardless of caption, and compose
`caption\n\nbody` so the owner's «це на завтра» still rides along for the intent call. An
unreadable document (binary, oversized) falls back to the caption alone, which is today's
behaviour.
