# t1245 — changes.py treats an empty day argument as today

## Problem / goal

`status/changes-send.sh` calls the collector as `changes.py "${1:-}"`, so when the
23:30 timer (and the `/changes` command) run it with no argument, an **empty string**
is still passed as `argv[1]`. `changes.py:16` takes `sys.argv[1]` whenever
`len(sys.argv) > 1`, so `day=""`, the probe looks for `changelog/.jsonl` (never
exists) and reports «Змін за  немає — журнал порожній». Confirmed in production:
`status/state/chat-log.jsonl` shows exactly that text at 23:30 every day from
2026-11-11 through 2026-11-22, while `changelog/2026-11-22.jsonl` alone holds 440
events. The nightly change summary has effectively been dead — and stating a
falsehood — for over a week. (Nightly review 2026-11-23, High.)

## Test cases

- **TC1 (regression) —** given today's date, when `changes.py ""` is run, then the
  reported `value.day` is today's `YYYY-MM-DD`, not the empty string, and the text
  does not contain «Змін за  немає» (double space = empty day). Fails before the
  change, passes after.
- **TC2 —** when `changes.py 1999-01-02` is run with an explicit date, then
  `value.day == "1999-01-02"` — an explicit argument is still honoured.

## Approach

One line in `status/probes/changes.py`: an empty or whitespace `argv[1]` falls back
to today, same as no argument. The shell caller is left as is — fixing the collector
covers every caller (the timer, `/changes`, manual runs).
