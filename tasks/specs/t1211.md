# t1211 — a failed morning biorhythms run says so in the chat

## Problem / goal

`noos-bio.timer` runs `mood.py --only bio` at 08:20. `write_biorhythms` calls
`run_claude`, which raises RuntimeError on a non-zero exit (an expired login — the exact
condition the auth probe exists for) or propagates TimeoutExpired after the model call
times out. Neither is caught on the `--only bio` path: main() dies with a traceback,
nothing watches the unit's exit code, and the `bio` probe reports a stale state as
ok=true («ще не рахувались»), so the watcher stays quiet too. The morning biorhythms
message silently never arrives — the exact failure mode t1160/t1196/t1200 closed for
mood2, which the still-live bio path lacks. Found by the nightly self-review of
2026-11-19 (Medium).

## Test cases

- **TC1 —** given `write_biorhythms` raising RuntimeError, when `main(--only bio)` runs
  without `--dry-run`, then a failure notice is sent (through the same mood role the bio
  message itself uses) and the exit code is non-zero. (regression — fails before the
  change: the exception propagates and no notice is sent)
- **TC2 —** given the same failure under `--dry-run`, the exception propagates unchanged —
  an interactive run wants the traceback, not a Telegram message.
- **TC3 — edge:** a broken notify.sh inside the failure notice never masks the real exit
  code (report_failure swallows its own errors, as in mood2).

## Approach

Add `report_failure(text)` to mood.py — notify.sh with `--bot mood` when configured,
never raises (the mood2 pattern, t1160/t1196) — and wrap the `--only bio` branch:
on any exception, when not dry-run, send «Біоритми сьогодні не порахувались…», print the
error to stderr and return 1. The astrology path keeps its existing failure handling.
