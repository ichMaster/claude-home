# t1084 — panel: the fact pin buttons are inverted

Found by the phase-7 review (eeade71, finding M1 in
`status/state/code-review/2026-10-31-panel-phase7-scan.md`).

## Problem

`memory_action` maps «вище» to `pin + 1` and «нижче» to `pin - 1`, but the prompt ranks
pins **ascending**: pin 1 is critical and always first, pin 2 fits if room is left, pin 0
never enters. So «вище» on a pin-1 fact demotes it to pin 2 — behind every pin-1 fact and
possibly out of the prompt entirely (the exact «не влізли» bucket the screen exists to
expose) — and «вище» on a pin-2 fact clamps to 2 and does nothing: the button can never
do what it says. «нижче» on pin 2 promotes.

## Fix

A priority ladder instead of arithmetic: up `0→2→1` (1 stays), down `1→2→0` (0 stays).
A pin outside 0/1/2 (hand-edited file) is treated as 1 rather than crashing the POST.
One `memory_screen.facts()` call instead of three while on that line.

## Test cases

Each asserts the level handed to `facts.py pin` (run_script stubbed):

- **TC1** — «вище» on pin 2 → `1`. (Fails before the fix: stays `2`.)
- **TC2** — «вище» on pin 0 → `2`; on pin 1 → stays `1`.
- **TC3** — «нижче» on pin 1 → `2`; on pin 2 → `0`; on pin 0 → stays `0`.
- **TC4** — a pin outside 0/1/2 does not crash the action.
