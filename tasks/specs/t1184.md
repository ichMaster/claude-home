# t1184 — an invalid first dotted date hides a later valid one

## Problem / goal

The dotted-date branch of `parse_due` uses `re.search`, computes the date, and on
ValueError (t1048: «31.11», «python 3.14») sets `when = None` and falls through — without
ever trying a later match. Reproduced: «оплатити 31.11 і ще 20.12 рахунок» returns
`(None, unchanged)` although the text carries a perfectly good 20.12 — the task is stored
with no deadline and the probe never warns.

## Test cases

- **TC1 — regression:** «оплатити 31.11 і ще 20.12 рахунок» → due 20.12, the 31.11 left in
  the title (fails before: None).
- **TC2:** t1048 behaviour holds — «оновити python 3.14» and «звіт до 31.11» still parse
  no date and keep their text.
- **TC3:** the first match wins when both are valid: «зустріч 20.11 або 25.11» → 20.11.

## Approach

`re.finditer` over the same pattern; take the first match that builds a valid date, keep
the year-rollover logic (t1088) per match. No valid match → fall through as before.
