# t1160 — mood2 failures at 08:15 are silent; --send must say when it could not deliver

## Problem / goal

`noos-mood2.timer` runs `mood2.py --send`; `main()` turns `NoCalendar` into exit 4 and
`StageFailed`/`Unfaithful` into exit 3, printing only to stderr (the journal). No `OnFailure=`
exists and no probe watches the unit, so the reading simply never arrives, with no sign why.
This is imminent, not theoretical: the forwarded calendar coverage ends 2026-11-15 and v1 is
stopped — from the 16th every morning would fail silently. Stopping on an uncovered day is
the design; stopping *silently* is not («silence is the honest answer» covers not inventing a
reading, not hiding that the run stopped).

Found by the nightly code review, 2026-11-12 (scan report, Medium #3).

## Test cases

- **TC1 —** given `--send` and a day with no reference calendar, `main()` still exits 4 AND
  notify.sh is called once with a message naming the reason (regression: before the fix,
  nothing is sent).
- **TC2 —** the same failure *without* `--send` sends nothing (a manual dry run must not
  spam the chat).
- **TC3 —** a notify.sh that itself fails does not change the exit code.

## Approach

A `report_failure()` helper around notify.sh (check=False, wrapped in try) called from the
`NoCalendar` and `StageFailed`/`Unfaithful` handlers only when `args.send` is set — the timer
is the only caller that passes it. The message is plain Ukrainian, built from the exception
text, which is already written for a person.
