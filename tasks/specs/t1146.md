# t1146 — astro2: invented natal item passes check_items when source has no natal marker

## Problem / goal

`check_items()` in `status/mood2.py` counts natal markers one-directionally and gated:
`if natal_source and natal_items < natal_source`. When the reference day contains no
«Событие влияет» / «Подія впливає» line, `natal_source == 0` and the gate makes any number
of model-invented `kind="natal"` items pass with zero problems. `mandatory_ids()` then
marks every natal item mandatory, `selection()` restores it past the pick stage, and the
final reading asserts a personal transit the reference astrologer never wrote — silently,
with the run reported as faithful. This contradicts the function's own contract: "an
invented one would put a claim in his mouth".

The over-count direction when `natal_source >= 1` stays deliberately unchecked: one marker
legitimately covers several «на мій <планета>» lines
(`test_two_natal_lines_may_share_one_interpretation`). Only the `natal_source == 0` case is
a pure fabrication — natal lines appear exclusively under the marker in his layout
(`tests/data/reference-day.txt`).

Found by the nightly code review of 2026-11-11 (M1), confirmed by execution.

## Test cases

- **TC1 (regression) —** given a source with no natal marker and an item list containing a
  fabricated `kind="natal"` item, `check_items()` returns a problem naming the invented
  natal hit. Fails before the change (returns `[]`), passes after.
- **TC2 —** given a source with one marker and exactly one natal item, `check_items()`
  still returns no natal problem (the legitimate case is untouched).
- **TC3 — edge:** given a source with one marker and two natal items (shared
  interpretation), still no problem — the over-count direction stays permitted.

## Approach

One `elif` branch after the existing undercount check: `natal_items and not natal_source`
appends a problem. TC2/TC3 are already covered by existing tests
(`test_natal_undercount_is_flagged`, `test_two_natal_lines_may_share_one_interpretation`);
TC1 is the new regression test. Nothing else changes — `mandatory_ids`, `selection`,
prompts untouched.
