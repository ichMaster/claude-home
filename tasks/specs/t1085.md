# t1085 — the panel can be framed: no X-Frame-Options / CSP frame-ancestors

## Problem / goal

Nightly review 2026-11-01. `_send()` in `panel/server.py` emits only Content-Type and
Content-Length. The panel is unauthenticated, listens on `0.0.0.0`, and `host_ok()` accepts
any IP literal — so a hostile web page in the owner's browser can iframe
`http://<LAN-IP>:8091/memory`, the framed page arrives with the live `FORM_TOKEN` embedded
in its forms, and an invisible button overlaid under a decoy fires a genuine same-origin
POST: a deleted fact, a closed task in the append-only log, an eight-minute recalc. The
FORM_TOKEN and Host checks both target cross-origin posting, not framing — clickjacking
walks around both.

## Test cases

- **TC1 —** given the live panel, when any page is fetched over HTTP, then the response
  carries `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`
  (regression — fails before the change).
- **TC2 —** the 303 redirect after a POST carries the same headers, so no response of the
  panel is frameable.

## Approach

Add the two headers once, where every response passes: `_send()` and `_redirect()` (plus
the inline 303 in the `/tasks` branch, which builds its response by hand). Nothing else —
no CSP policy beyond frame-ancestors, the panel serves its own inline styles.
