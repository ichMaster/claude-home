# t1163 — a ПЕРЕДАТИ line born from fetched web content must not reach the main chat

## Problem / goal

Bruno's search mode puts up to 1800 characters of raw fetched page text per hit into the
answering prompt. `split_handoff()` trusts any `ПЕРЕДАТИ:` line in the model's output, and
`hand_over()` seeds a second model call with it and sends the result to the owner's MAIN chat
in the assistant's default voice. An SEO'd article containing a planted «ПЕРЕДАТИ: …» line
therefore becomes a plausible, assistant-voiced instruction in the channel where real
commands are given — prompt injection crossing from a read-only content bot into the control
channel.

Found by the nightly code review, 2026-11-12 (scan report, Medium #6, security).

## Test cases

- **TC1 —** given a Bruno search reply whose text carries a `ПЕРЕДАТИ:` line, when
  `handle_update` runs, then `hand_over` is NOT called and the line still never appears in
  the chat reply (regression: before the fix the handoff fires).
- **TC2 —** a `ПЕРЕДАТИ:` line in a non-search reply (no web content in the prompt) still
  hands over — the legitimate flow keeps working.

## Approach

When the prompt carried web search results (`bot == "bruno"` and `search` non-empty), a
`ПЕРЕДАТИ` line is stripped as always but discarded instead of handed over, with a printed
note and a `dropped.jsonl` record. A search answer has no legitimate need for a handoff: the
handoff path exists for settings/action requests, which are not search mode. Zirka's `search`
slot holds only owner-forwarded or internally generated text, so she is untouched.
