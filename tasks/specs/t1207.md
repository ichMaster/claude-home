# t1207 — headless sessions on untrusted input can write files and read secrets

## Problem / goal

The three headless senders that read text anyone on the internet can write — the digest and
social sessions read inbound mail through the Gmail connector, the YouTube session reads RSS
titles from 600 channels — all run `claude -p` with `--permission-mode acceptEdits` and with
`Bash(cat:*)`, `Bash(head:*)`, `Bash(tail:*)` in `--allowedTools`:

- `acceptEdits` auto-approves the Write/Edit tools, which `--allowedTools` does not
  restrict. An injected mail can steer the session into writing persistent content into
  repo files the trusted contexts later execute or obey (`CLAUDE.md`, `status/run.sh`,
  a prompt file) — the t1186 Bash hardening, one step removed.
- `Bash(cat:*)` (and `head`/`tail`) match `cat .env.telegram`,
  `cat ~/.claude/.credentials.json`, `cat ~/.claude/.env.oauth` — live tokens pulled into
  the model context and transcript, which memory ingestion then indexes.
- The built-in Read tool is allowed by default in headless runs, so it reaches the same
  secret files without Bash at all.

The t1186 comment in `digest-headless.sh` states the allowlist exists precisely because
"an allowlist of everything turns a prompt injection into arbitrary command execution";
the edit and cat paths reopen exactly that. Found by the nightly self-review of
2026-11-19 (High). `code-review-headless.sh` is out of scope: it reads the repo's own
code, not foreign text, and needs Write/Edit to do its job.

## Test cases

- **TC1 —** given the three untrusted-input headless scripts, when their non-comment text
  is inspected, then none carries `--permission-mode acceptEdits` and each disallows the
  file-writing tools (`Write`, `Edit`, `MultiEdit`, `NotebookEdit`) explicitly. (regression —
  fails before the change)
- **TC2 —** given the same scripts, when the `--allowedTools` rules are read, then no rule
  allowlists `cat`, `head` or `tail`. (regression — fails before the change)
- **TC3 —** given `status/digest-settings.json` (shared by all three), when its permissions
  are read, then Read is denied on `.env*`, `config.local.json` and the Claude credential
  files. (regression — fails before the change)
- **TC4 — edge:** `bash -n` still passes on every edited script (covered by the existing
  t1186 suite, re-run).

## Approach

Smallest change in each of `status/digest-headless.sh`, `status/social-headless.sh`,
`status/youtube-headless.sh`: drop `--permission-mode acceptEdits`, add
`--disallowedTools "Write" "Edit" "MultiEdit" "NotebookEdit"`, and remove the
`cat`/`head`/`tail` Bash rules (they were "harmless text helpers"; the Read tool covers
legitimate reads and is itself now fenced off the secrets). Add a `permissions.deny`
block to `status/digest-settings.json` for Read on `./.env*`, `./config.local.json`,
`~/.claude/.credentials.json`, `~/.claude/.env.oauth`. Prompts are not changed.
