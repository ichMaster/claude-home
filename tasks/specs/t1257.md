# t1257 — digest allowlist narrowed to read-only store.py list

## Problem / goal

`status/digest-headless.sh` allowlists `Bash(.venv-voice/bin/python tasks/store.py:*)`,
which auto-approves every store.py subcommand — add, done, cancel, defer, edit, link —
while `status/digest-prompt.md:38` only ever needs the read-only `store.py list --all`.
The same session reads inbound Gmail text (anyone on the internet can write it), and
the script's own t1186/t1207 comments name injection-to-execution as the live threat:
a crafted email can make an injected model silently cancel or close the owner's open
tasks, and the events land in the append-only log looking legitimate.

Same pattern in `status/social-headless.sh`: `status/probes/youtube.py:*` covers
`--drain`, so an injection in a Facebook mail could blank the 18:05 video digest —
while social-prompt.md never invokes youtube.py at all (polling moved to
noos-youtube-poll.service).

youtube-headless.sh keeps its `youtube.py:*` rule: its prompt legitimately runs
`--drain`, and the rule grants nothing beyond what the script exists to do.

## Test cases

- **TC1 —** any `tasks/store.py` rule in a headless allowlist is pinned to the `list`
  subcommand (regression: digest-headless.sh carries the broad `store.py:*` before).
- **TC2 —** the youtube.py rule in social-headless.sh is exact (no `:*`), so `--drain`
  is not auto-approved there (regression: wildcard before).
- **TC3 —** digest still works: the prescribed `store.py list --all` matches the
  narrowed prefix rule (string-level check that the rule prefixes the prompt's call).

## Approach

Two one-line allowlist edits; a new test in tests/test_headless_allowlist.py beside
the t1186/t1220 guards. Nothing else changes.
