# t1106 — the schedule field could not express two times, and a comma changed the schedule

Found by the full review, 2026-11-01 (writes H3 and M3 in
`status/state/code-review/2026-11-01-panel-full-writes.md`).

## Problem

The field is a single-line `<input>` prefilled with `"; ".join(schedules)`; the action split
the submitted value on `","` and newlines. A text input cannot carry a newline, so the only
separators a browser can produce are `;`, which the action did not split on, and `,` —
**systemd's own separator inside one spec**.

Two consequences:

- The three timers that carry more than one time — the digest (08:03 and 20:03), the YouTube
  poll, the social run — answered «systemd не приймає …» to the button no matter what. The
  schedule they already had could not be re-submitted. The feature was unreachable for
  exactly the case its docstring cites.
- A legitimate spec whose comma-separated fragments are *also* valid was silently split into
  a different schedule: `Mon,Tue *-*-* 09:00:00` became `OnCalendar=Mon` (Monday midnight)
  plus `OnCalendar=Tue *-*-* 09:00:00`, written, reloaded and reported as
  «розклад тепер Mon, Tue *-*-* 09:00:00».

The suite was green because `tests/test_panel_edit2.py` submitted a newline-separated value —
a separator the rendered form cannot produce.

Separately (M3): the result of `daemon-reload` was discarded, and the `LoadState` check that
follows still answers «loaded» for the unit systemd holds in memory, so a failed reload was
reported as a successful schedule change. The file and the running timer then disagree, and
the symptom of a wrong timer is silence.

## Fix

- `schedule_specs()` splits on `;` and newlines only, never on a comma.
- `schedule_prefill()` joins with the same separator, so what the form offers can be
  submitted back unchanged.
- The field is rendered only where there is an `OnCalendar` line to edit: `schedule_rows`
  now reports `calendars` separately from the `schedules` it displays, so an interval timer
  no longer gets a calendar field.
- A failed `daemon-reload` restores the previous unit, reloads again, and says so.

## Test cases

- **TC1 —** `;` and newlines both separate specs. (Fails before for `;`.)
- **TC2 —** a comma inside a spec is left alone. (Fails before: it splits.)
- **TC3 —** the prefill round-trips: what the form shows parses back to the same specs.
- **TC4 —** an interval timer gets no calendar field.
- **TC5 —** a failed `daemon-reload` is reported as a failure and the unit is put back.
