# t1222 — alarm level escalation changes the watch signature

## Problem / goal

The alarm probe computes the alert level (yellow/red — red is «a heightened threat»,
status/probes/alarm.py:39-48) and puts it in both the text and the value, but the watcher's
change signature for alarm is only `district_alert|region_alert` (status/watch.py:57). An
alert that starts yellow and escalates to red twenty minutes later produces no change:
nothing is sent until the 3-hour reminder (`watch.remind_after_sec`), or never if the alert
ends first. De-escalation red→yellow is equally invisible. The level was added to the probe
on 2026-10-31 (df56eeb) without extending the signature.

## Test cases

- **TC1 —** given two alarm probe results identical except `level` («yellow» → «red»), when
  `signature()` is computed, then the signatures differ (regression — fails before the
  change).
- **TC2 — edge:** unchanged level keeps the signature stable, so no duplicate alerts.

## Approach

Append `|{v.get('level')}` to the alarm branch of `signature()` in `status/watch.py`.
