# t1247 — a wedged docker daemon must not stall the services probe

## Problem / goal

`status/probes/services.sh` runs `docker ps` with no time bound. t1208 handled a
daemon that **errors**; a daemon that **hangs** (the real t1201 incident mode)
blocks the probe inside run.sh's sequential loop. run.sh prints its output only
after the loop, so the alarm/loe/auth results already gathered are lost too;
watch.py kills the whole group at `PROBE_TIMEOUT` (300 s) and keeps nothing —
«run.sh не відповів … стан не чіпаю», journal-only. Every 15-minute run repeats
this, so an air-raid alert or an auth expiry during a docker wedge is never
delivered, and nothing tells the owner the watcher is blind. (Nightly review
2026-11-23, Medium, verified.)

## Test cases

- **TC1 (regression) —** given a `docker` stub that sleeps far longer than the
  bound, when services.sh runs with a 1-second `SERVICES_DOCKER_TIMEOUT`, then it
  still prints valid JSON within a few seconds, with the named «docker не
  відповідає» warn — the same degradation as a dead daemon. Fails (hangs past the
  test timeout) before the change.
- **TC2 —** the t1208 cases still hold: an erroring daemon is a named warn, a dead
  tmux alert survives a docker outage, the happy path keeps its shape.

## Approach

Wrap both `docker ps` calls in `timeout "$dto"`. The bound comes from
`probes.services.docker_timeout` in `config.json` (10 s), overridable with
`SERVICES_DOCKER_TIMEOUT` (which also keeps the test fast and offline); a missing
value falls back to 10. A killed docker lands in the existing else branch from
t1208 — named warn, probe JSON intact. run.sh's buffering and watch.py's group
kill are left as they are: with every probe bounded at its own source, the
300-second group bound stops being reachable through docker.
