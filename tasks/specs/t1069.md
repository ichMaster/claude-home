# t1069 — the panel rejects a foreign Host: DNS rebinding protection

Found by the phase-3 review (92bf21c, t1068), finding M1 in
`status/state/code-review/2026-10-31-panel-phase3-scan.md`.

## Problem / goal

The form token minted at process start (t1068) is meant to stop a page on another origin
from driving the panel. DNS rebinding bypasses it entirely: an attacker's page at
`http://evil.example:8091` re-resolves its own domain to the panel's address — the panel
has listened on `0.0.0.0:8091` since 2026-10-31 — after which the attacker's script is
*same-origin* with the panel. It can `fetch("/zirka")`, read the token out of the hidden
inputs, POST any action with it, and exfiltrate everything the panel renders (the forecast
log, feedback, rules, the commit log) to the internet. The victim only has to visit a web
page from any device on the LAN.

Every such request necessarily arrives with a `Host` header naming a DNS domain the
attacker controls. The owner reaches the panel by IP (or a tailnet name); no legitimate
request carries `Host: evil.example`. Checking Host is the standard and sufficient defence,
and it is the mechanism that actually enforces the boundary the design declares («the trust
boundary is the network», ADMIN-PANEL.md § Technical shape).

## Test cases

- **TC1 — regression, the guard exists and rejects DNS names.** `host_ok("evil.example:8091")`
  is False; `host_ok` accepts `127.0.0.1:8091`, `192.168.1.5:8091`, `[::1]:8091`,
  `localhost:8091`, a `*.ts.net` name, and a missing header (non-browser clients; rebinding
  needs a browser, and browsers always send Host). Fails before the change — the function
  does not exist.
- **TC2 — wired into GET.** A real request to a live Handler with `Host: evil.example:8091`
  gets 403; the same request with the loopback Host gets 200.
- **TC3 — wired into POST, before the token check.** A POST with a *valid* token but a
  foreign Host gets 403 — the token must not be treated as proof once the origin is the
  panel's own.
- **TC4 — edge:** `panel.hosts` in config may add extra allowed names.

## Approach

`host_ok(header)` in `panel/server.py`: strip the port (brackets for IPv6), then accept an
IP literal (`ipaddress.ip_address`), `localhost`, a name ending in `.ts.net` (MagicDNS —
an attacker cannot rebind a name under Tailscale's domain), or a name listed in
`panel.hosts`. Both `do_GET` and `do_POST` check it first and answer 403.

Out of scope: authentication (explicitly refused by the design), Origin/Referer checks
(Host alone closes the rebinding hole, and the token already covers classic cross-origin
POSTs).
