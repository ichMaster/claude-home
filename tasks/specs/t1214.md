# t1214 — Zirka recalc launches the stopped v1 pipeline

## Problem / goal

«Перерахуй прогноз» in Zirka's chat runs `recompute_forecast`, which systemd-runs
`status/mood.py --day <day>` — the v1 pipeline, with no `--only`/`--dry-run`, so it sends
BOTH v1 messages (biorhythms and v1 astrology). Since 2026-11-12 v1 astrology is stopped
by the owner's explicit order («першу версію треба взагалі зупинити»): `noos-mood.timer`
is gone and the morning reading is `mood2.py`, built from the astrologer's calendar. The
recalc therefore delivers a reading from the deprecated pipeline, presented as the new
reading, diverging from that morning's real v2 reading. Found by the nightly self-review
of 2026-11-19 (Medium).

## Test cases

- **TC1 —** given a recalc request, when `recompute_forecast` builds its command, then it
  launches `mood2.py` with `--send` and the asked day — not `mood.py`. (regression —
  fails before the change)
- **TC2 —** the unit-name lock and the failure wording survive unchanged (existing
  tests: a second run is refused, a failed start is reported).

## Approach

Point the systemd-run command at `status/mood2.py --day <day> --send` and keep
everything else (unit name as lock, timeouts, messages) as is; soften the fixed
«хвилин за вісім» to «за кілька хвилин», since the v2 pipeline's length is its own.
v2's own failure path (t1196/t1200) already reports into her chat when the day cannot
be read.
