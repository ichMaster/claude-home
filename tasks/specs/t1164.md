# t1164 — handoff.py can build the note from a headless transcript

## Problem / goal

`handoff.py` picks the transcript by newest mtime in
`~/.claude/projects/-home-ich-claude-home/`. Every headless `claude -p` run with this cwd —
the 20:03 digest, social checks, the bots inbox, mood2 stages — writes its transcript into
the same directory, so whenever one of them ran after the owner's last exchange (the digest
does daily), the 05:00 note is built from a probe run's prompt-and-answer instead of the
day's conversation. The thread the clean restart exists to carry over is silently replaced.

Found by the nightly code review, 2026-11-12 (scan report, Medium #7).

## Test cases

- **TC1 —** given an older transcript with several real user turns and a newer one with a
  single user turn (the shape of every `claude -p` run), the picker chooses the older,
  conversational one (regression: before the fix the newest always wins).
- **TC2 —** when no transcript reaches the threshold, the newest is used — a fallback beats
  no note at all.

## Approach

A transcript is "the conversation" when it carries at least `memory.handoff_min_user_turns`
(3) user text turns — a headless `-p` run has exactly one. Walk the files newest-first and
take the first that qualifies; parsing is the same turn extraction the note already uses.
The script body moves into functions (`parse_turns`, `pick_transcript`, `main`) so the picker
is testable; behaviour is otherwise unchanged.
