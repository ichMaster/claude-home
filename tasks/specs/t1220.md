# t1220 — headless allowlists drop echo, closing shell-redirection writes

## Problem / goal

t1207 (8db8d07) removed `acceptEdits` and disallowed Write/Edit in the three headless
sessions that read untrusted input (mail, facebookmail, RSS titles) — but all three kept
`"Bash(echo:*)"` in `--allowedTools` (status/digest-headless.sh:36,
status/social-headless.sh:20, status/youtube-headless.sh:19). A Bash prefix rule matches
the start of each simple command, and an output redirection is part of that command, so
`echo 'нова інструкція' >> CLAUDE.md` (or `>> .claude/settings.json`, or
`> .claude/commands/x.md`) is auto-approved. That re-opens the exact persistence channel
the t1207 commit says it closed: injected text written into a file the trusted main session
later obeys. Nothing in the three prompts uses `echo`.

## Test cases

- **TC1 —** no allowlisted Bash rule in any of the three scripts has a write-capable prefix
  (`echo`, `printf`, `tee`, `dd`, `sed`, `cp`, `mv`) — fails before the change on `echo`.
- **TC2 — edge:** the scripts stay valid shell (`bash -n`), covered by the existing test.

## Approach

Delete `"Bash(echo:*)"` from the `--allowedTools` of all three scripts; extend
`tests/test_headless_allowlist.py` with the write-prefix assertion so the gap cannot
reopen. `date:*` and the named repo scripts remain.
