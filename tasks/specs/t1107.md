# t1107 — a save on a damaged `config.local.json` replaced it with a stub

Found by the full review, 2026-11-01 (writes-H1's twin: **writes H2** in
`status/state/code-review/2026-11-01-panel-full-writes.md`).

## Problem

`rules_screen._local_config()` caught `JSONDecodeError` and returned `{}`. So a
`config.local.json` that was there but would not parse — exactly what the temp-file race in
t1104 produced — read as "no local configuration at all", and one press of «зберегти» wrote
back a document containing only the key just edited:

```
before: 14244 bytes, parses: False
  set_setting -> (True, 'probes.youtube.per_run = 40; діє після перезапуску…')
  file after:  {"probes": {"youtube": {"per_run": 40}}}
  channels still there: False   birth data still there: False
```

The 603-channel polling list, the birth data, the calendar id and the voice ids — the only
copy of each — replaced, and the panel said it worked. The version copy was taken, so
`tools/versions.py restore` could get it back; nobody would look, because the message was a
success.

The other two writers of that file get it right (`sources_screen` raises `RuntimeError`,
`permissions.set_level` returns False), which is what makes this a defect rather than a
design choice.

## Fix

`_local_config()` raises `LocalUnreadable` — never `{}` — and both `set_setting` and
`reset_setting` answer the refusal in words, naming `tools/versions.py list` so the recovery
is one line away. An absent file still means an empty one: a fresh machine has no local
config, and the first save has to create it.

## Test cases

- **TC1 —** a save against a truncated local config refuses, says the file does not parse,
  and leaves it byte-for-byte. (Fails before the fix: the file is replaced with a stub.)
- **TC2 —** a reset against the same file refuses too.
- **TC3 —** the refusal names the recovery path.
- **TC4 —** an absent local config is not an error: the first save creates it.
