# t1090 — panel: phase 8, the Rules screen, read-only

Screen 8 of `docs/features/ADMIN-PANEL.md`, the last of the reading screens. The owner
narrowed the phase on 2026-11-01: **this phase only reads.** Editing configuration,
permissions and timer schedules becomes a phase of its own, after the panel has
authentication — see the doc change in this task.

## Problem / goal

Four kinds of state govern this assistant and none of them is visible without a terminal:

- **Configuration.** `config.json` holds the defaults, `config.local.json` overrides them
  key by key, and the merged result is what every probe actually obeys. Today the only way
  to see which value won is to read two files and merge them by eye.
- **Permissions.** The panel doc promised switches. There are no switches to show: the
  session runs under `--permission-mode auto` with no allow/deny list configured anywhere,
  and the real rules are prose in `CLAUDE.md`. A screen of toggles would be a screen of
  decoration — worse, it would claim to govern something it does not.
- **The schedule.** 15 systemd user timers. "Why did the digest stay silent" is answerable
  only through `systemctl --user list-timers` and `journalctl`.
- **Keys.** Which `.env` files exist at all. `.env.gmail` and `.env.calendar` are missing
  on this machine right now, which is why the mail and calendar probes warn instead of
  answering — and nothing in the system says so where it can be seen.

So: one screen that shows all four, honestly, and writes nothing.

## Test cases

- **TC1 — settings.** A key present in both files renders as overridden with the default
  beside the effective value; a key only in `config.json` renders as default and is not
  marked overridden; a key only in the local file renders as local-only.
- **TC2 — masked values.** A key whose dotted path starts with one of `panel.rules_masked`
  (birth data, the calendar id, the subject contexts, the voice ids) renders as
  «значення приховано» and its value appears **nowhere** in the HTML. The panel listens on
  the tailnet with no authentication; personal values do not belong on it.
- **TC3 — collections.** A list value renders as its length («список, 603 елементи»), not
  dumped, and a long string is truncated.
- **TC4 — schedule.** A timer with two `OnCalendar` lines shows both (the digest runs
  twice a day). A timer whose service never ran says «не запускався». A service whose
  `Result` is not `success` is marked failed with its result and exit status. A timer that
  runs on an interval and has no `OnCalendar` at all shows its interval, not «—»: four of
  the 15 are like that, including the watcher and the bots.
- **TC5 — keys.** A present env file shows its mode, size and the **names** of the
  variables in it, with «задано» / «порожнє» per name. A missing file says «немає» and
  names the example to copy. No value from any file reaches the HTML.
- **TC6 — the standing rules stay honest.** Every prose rule listed on the screen names the
  file it comes from, and the test asserts that file still contains the rule's anchor text.
  A rule deleted from `CLAUDE.md` must fail this test rather than keep being displayed.
- **TC7 — the screen.** `GET /rules` answers 200, carries the four section headings, and is
  no longer the «фаза 8» placeholder.
- **TC8 — read-only and no command injection.** `POST /rules` is 404 — the screen has no
  form. `?unit=` naming anything outside the known timer and service units never reaches
  `journalctl`; it answers with a refusal.

## Approach

- `panel/rules_screen.py` — collectors, pure where they can be: `setting_rows()`,
  `value_text()`, `schedule_rows()`, `key_rows()`, `standing_rules()`, `permissions()`.
  Anything that shells out (`systemctl show`, `journalctl`) stays in `server.py`, as on
  every other screen, so the tests never touch systemd.
- `panel/render.py` — `render_rules()`, same vocabulary as the other screens.
- `panel/server.py` — `/rules` leaves `SOON`; GET only, `?unit=` for a journal tail with
  the unit validated against the list systemd itself reported.
- `config.json` — `panel.rules_masked`, `panel.journal_lines`, `panel.key_files`.
- `docs/features/ADMIN-PANEL.md` — phase 8 is read-only; a new **phase 10 — Editing**
  carries the forms, after authentication.

Out of scope, deliberately: writing anything, switches that pretend to be permissions,
rewriting unit files, and showing a single secret value.
