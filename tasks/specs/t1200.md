# t1200 — mood2 main catches any exception and reports the silent morning

## Problem / goal

`mood2.main()` catches only the typed pipeline errors (`Unconfigured`, `MissingPrompt`,
`NotReady`, `NoCalendar`, `StageFailed`, `Unfaithful`, `Undelivered`). Anything else — disk
full raising `OSError` in `log_run()`, `FileNotFoundError` from a vanished `claude` binary,
a `KeyError` on unexpected state — dies with a raw traceback: `report_failure` never runs,
nothing arrives in Zirka's chat and nothing announces the miss. That is exactly the
silent-morning failure t1160 and t1196 were written to close, still reachable through every
exception class outside the typed five. Found by the nightly review of 2026-11-17 (Medium).

## Test cases

- **TC1 — regression:** given a `--send` run whose pipeline raises `OSError`, `main()`
  returns a distinct exit code (6) instead of propagating, and `report_failure` was called
  with a message naming the error (fails before the change: the exception propagates).
- **TC2 —** without `--send` the same failure still returns 6 and prints to stderr, but does
  not notify — a dry or manual run speaks to the terminal, not to her chat.
- **TC3 —** the typed errors keep their own codes: a `NoCalendar` day still exits 4 through
  its own branch, not through the catch-all.

## Approach

One final `except Exception` branch in `main()`, after the typed ones: print
`class: message` to stderr, call `report_failure` under `--send`, return 6. `SystemExit` and
`KeyboardInterrupt` are not `Exception` subclasses, so a deliberate exit and Ctrl-C stay
untouched. The typed branches stay first and keep their codes. Out of scope: the systemd
`TimeoutStartSec` arithmetic (reported as Low, not fixed here).
