# t1099 — panel: authentication becomes phase 11

The owner's request, 2026-11-01: «додай в 11». Plan only — this task writes the design down,
it builds nothing.

## Problem / goal

Authentication sat in the panel's «not a phase» list from the start, on the reasoning that a
login form on a loopback socket reached through an SSH tunnel is decoration. Two things
changed:

- On 2026-10-31 the owner bound the panel to the whole local network (`panel.host` →
  `0.0.0.0`) because he works from another machine. The reasoning that made a login
  pointless went with it.
- Phase 8's review then found the journal pane publishing his calendar across that network
  (t1094), and phase 10 — editing — turned out to be blocked by a decision that belonged to
  no phase at all. A blocker nobody scheduled is a blocker forever.

## The design

- **Narrow the bind back to the tailnet.** `panel.host` → `tailscale`: his own devices, with
  WireGuard between them. Already implemented (`resolve_host`), one setting, and it removes
  the entire class of "someone else on the Wi-Fi".
- **One shared password, stored as a hash.** One person, so no accounts and no roles.
  `hashlib.scrypt` with a random salt — stdlib — in `.env.panel` (mode 600, git-ignored),
  written by `panel/auth.py set` from a terminal prompt that neither echoes nor logs it.
- **Fail closed.** No password file → the panel serves only `/login` and the one line that
  says how to set one. It must never read "unconfigured" as "open".
- **A session token in memory only.** 32 random bytes, `hmac.compare_digest` on the hash,
  expiry `panel.auth.ttl_hours` (12), cookie `HttpOnly` + `SameSite=Strict`. A restart logs
  out; no second secret lands on disk.
- **Rate limiting and a log.** Five failures per source address, then a five-minute lock;
  every attempt appended to `status/state/panel-auth.jsonl`. The log matters as much as the
  lock — an attempt from an address that is not his is something he should see.
- **The form token stays.** It stops a page on another origin from driving this one (t1069,
  t1085); a login does not replace it.
- **No TLS, said plainly.** On a tailnet address the traffic is encrypted between devices.
  If that stops being enough, the upgrade is `tailscale cert` — a real certificate for the
  `*.ts.net` name, no private CA. Out of scope here.

The real risk is a lockout, not a leak: so the phase's first tests are the three password
cases and an expired token, and its second deliverable is `panel/auth.py clear` as a
terminal escape hatch.
