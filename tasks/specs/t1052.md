# t1052 — start.sh: the in-process restart loop reuses stale ARGS and drops the conversation

## Problem / goal

`ARGS` is computed once before the `while true` loop. The default daily 05:00 restart
consumes `.fresh`, so `ARGS` has no `--continue`. If claude later exits in-process (crash,
OOM, `/exit`) without systemd restarting `start.sh`, the loop reruns the same stale `ARGS`:
a brand-new conversation with the morning's now-stale handoff note, silently discarding
everything said since the restart. CLAUDE.md's promise «a crash afterwards goes back to
continuing» held only for the systemd path.

## Test cases

- **TC1 (regression)** — run `start.sh` in a sandbox HOME with a `.fresh` flag and a stub
  `claude` that records its arguments, writes a transcript, and stops the loop after two
  runs: the first invocation has no `--continue`, the second one DOES.
- **TC2** — `bash -n start.sh` parses.

## Approach

Move the fresh/continue decision inside the loop: the `.fresh` flag applies to the first
iteration only; every later iteration re-checks for transcripts and continues. The restart
delay becomes `NOOS_RESTART_DELAY` (default 5) so the test does not sleep. The handoff note
staying in the rebuilt prompt on an in-process restart is unchanged (pre-existing, separate
concern).
