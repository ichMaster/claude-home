# t1190 — month-name date with impossible day crashes task add/defer

## Problem / goal

Found by the nightly review of 2026-11-16. `parse_due`'s month-name branch
(`до 31 листопада`) calls `date(y, mo, d)` with no guard, so an impossible day —
«до 31 листопада», «до 29 лютого» in a non-leap year — raises
`ValueError: day is out of range for month`. Both callers (`add`, `defer`) run it
unguarded, so `/task «купити квитки до 31 листопада»` from Telegram aborts with a
traceback **before** `append()` and the task is never written to the log. The dotted-date
branch directly below guards exactly this case (t1048/t1184); the month-name branch does
not, and no test covers the month-name form of an impossible day.

## Test cases

- **TC1 (regression)** — `parse_due("купити квитки до 31 листопада")` does not raise; the
  due date is None and the phrase stays in the title (a number that is not a date is text).
- **TC2** — `parse_due("звіт до 29 лютого")` in a year where next February has 28 days does
  not raise. (2027 and 2028 both reachable from 2026-11; the test freezes `today` so the
  outcome is deterministic.)
- **TC3 (fall-through)** — an impossible month-name date standing before a valid dotted one
  («до 31 листопада, крайній строк 20.12») still yields the dotted date, mirroring t1184.
- **TC4 (kept)** — a valid month-name date («до 20 грудня») still parses and is cut from
  the title.

## Approach

Mirror the dotted-date guard: build the date inside try/except ValueError and on failure
fall through to the later patterns without `cut_span`, so the impossible phrase becomes
plain title text instead of a crash. Smallest possible change; no other branch touched.
