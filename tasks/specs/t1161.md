# t1161 — mood.py --only bio never saves state, so the bio probe is stuck on yesterday

## Problem / goal

Since 2026-11-12 v1's full morning run is stopped and `noos-bio.timer` → `mood.py --only bio`
at 08:20 is the only thing that computes biorhythms. That branch does `log_run` and `send`
but never writes `astro.state` — `save_state` is only called by the full pipeline. The `bio`
probe compares `state["day"]` to today and, finding yesterday's date, answers «Біоритми на
сьогодні ще не рахувались» — forever, every day, even though the reading was computed and
sent that morning. Confirmed live: `astro.state` still said `day: 2026-11-11` on the 12th
after the 08:20 run.

Found by the nightly code review, 2026-11-12 (scan report, Medium #4).

## Test cases

- **TC1 —** given yesterday's state on disk, when `main(--only bio --day today)` runs, then
  the state file carries today's date and the fresh biorhythm figures, and yesterday's
  astrology summary is emptied, not re-dated (regression: before the fix the file is
  untouched).
- **TC2 —** given today's state with an astrology summary already in it, the bio run updates
  only the bio fields — the summary survives (the two readings stay two).

## Approach

A `save_bio_state()` that merges into the existing state file: same day → update
`biorhythms`/`bio_conclusion` only; different day → start a fresh record with empty astrology
fields. Called from the `--only bio` branch after `log_run`. The mood probe already treats an
empty `summary` as not-fresh (`fresh: bool(body)`), so an empty summary never shows a reading
he did not receive.
