# t1189 — auth probe false-positives on a wrapped reply quoting the login error

## Problem / goal

Found by the nightly review of 2026-11-16. `authcheck.classify()` treats any **non-bullet**
line whose stripped text starts with an expired pattern as the CLI's own error output. Two
reachable panes break that assumption:

- the session replies in the chat quoting «Login expired · Please run /login» (the natural
  conversation after any auth incident), and `tmux capture-pane` without `-J` emits the
  wrapped reply as separate physical lines — the quote lands on its own line without the `●`
  bullet;
- a reply lists the error on its own indented continuation line under its bullet;
  `.strip()` erases the indentation that distinguishes a continuation line from real CLI
  error output.

In both cases `pane_expired()` scans bottom-up, takes that line as the latest event and
returns True, so the watcher voices «Ноос не відповідає…» every three hours while the idle
pane keeps those lines in its last 80 — a false outage alert about a healthy session. The
t1187 tests only cover a quote on the same line as its bullet.

## Test cases

- **TC1 (regression)** — a pane whose last event is a `●` reply with the quoted error on its
  own **indented** continuation line → `pane_expired` is False.
- **TC2 (regression)** — `auth.capture()` passes `-J` to `tmux capture-pane`, so a reply
  wrapped by the terminal is rejoined with its bullet instead of leaving the quoted error on
  a column-0 line of its own.
- **TC3 (kept)** — the CLI's real error output at column 0 («Failed to authenticate: …»,
  «Login expired · …») still classifies as expired (existing tests TC1/TC4 of t1187).

## Approach

Two one-line changes: `capture()` adds `-J` so soft-wrapped lines are rejoined, and
`classify()` only lets the non-bullet expired branch fire for a line that starts at
column 0 — real CLI error output starts at the margin, a reply's continuation lines are
indented under their `●`. The substring-based `recovered` check is untouched (its own
looseness is a separate Low finding). Out of scope: hard-wrapped panes narrower than the
quote (the `-J` join covers the terminal's soft wrap, which is what capture-pane produces).
