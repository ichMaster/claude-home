# t1203 — the morning digest is built as the evening one

## Problem / goal

`noos-digest.timer` fires at 08:03 and 20:03, but the single `noos-digest.service` hardcodes
`ExecStart=… digest-headless.sh вечірній`, and the script never derives the part from the
clock — its `${1:-ранковий}` default is dead code, since nothing calls it argument-less. So
the 08:03 run substitutes `{{ЧАСТИНА}}=вечірній` too: the morning digest appends «Підсумок
дня» at 8 am and labels its news as evening news — confirmed in `chat-log.jsonl` every
morning of 11-13/14/16/17. The designed «ранковий» digest has never run. Found by the
nightly review of 2026-11-18 (Medium).

## Test cases

- **TC1 — regression:** the script invoked with no argument at an evening hour builds the
  prompt with «вечірній» (fails before the change: the dead default yields «ранковий»).
- **TC2 —** no argument at a morning hour → «ранковий».
- **TC3 —** an explicit argument still wins regardless of the hour — the Telegram `/digest`
  command passes the part by hand and must keep doing so.

Tests stub `claude` on `PATH` (it records its argv and exits) and pin the hour through
`NOOS_DIGEST_HOUR`, the test seam the script falls back from to `date +%H`.

## Approach

The script derives the part when no argument is given: before
`digest.morning_until_hour` (14, config.json) → «ранковий», else «вечірній». The deployed
`noos-digest.service` drops the hardcoded argument so both firings self-select (deployment
step beside the commit, with `daemon-reload` and a `systemctl --user cat` check). The
`/digest` command keeps its explicit argument. Out of scope: `TimeoutStartSec` for the three
headless-model units (reported as Low, a unit-only change flagged for the owner).
