## Problem / goal

**Screen 2 — Промпт** is the screen that justified the whole panel: showing the assistant to
itself. The system prompt the session wakes up with is assembled at launch by `start.sh` out
of `persona.md` plus `memory/facts.py prompt` plus, once, the handoff note — and then it is
invisible. Nothing in the running system can show it. Two consequences the owner hits in
practice: he cannot see what the session is actually told, and he cannot tell when an edit to
`persona.md` or `CLAUDE.md` is *in force* versus merely saved — those files are read at
launch, so a change means nothing until a restart.

**Screen 3 — Сценарії** is the other half: the prompts that belong to no channel — the
digest, the YouTube picks, the nine stages of the morning forecast, the bots' answering
prompts, the nightly review, the handoff note. They are plain files on disk that decide what
the automatic messages say, and today reading or re-running one means a terminal.

## What this builds

Both screens read. The editors for `persona.md` and `CLAUDE.md` belong to phase 10; the
scenario screen does get **run** buttons, because a run is not an edit and the panel has
pressed buttons like that since phase 3 (Zirka's recalc) — now behind a login.

- The assembled prompt, in the exact order `start.sh` builds it, with each part's size, the
  total, and a rough token estimate so the number means something.
- **A restart banner** when a file the session read at launch has changed since it started:
  `persona.md`, `CLAUDE.md`, or any file under `memory/facts/`. The session's start time
  comes from its own systemd unit, so nothing new has to be recorded anywhere.
- `persona.md` and `CLAUDE.md` rendered read-only, each saying whether it has uncommitted
  changes.
- The scenarios from `panel.scenarios` in config — name, prompt files with sizes, the unit
  that fires them and its schedule, the command — with *run* and, where the script supports
  it, *dry-run*. A long run is detached through `systemd-run` so the request returns at once;
  a dry run is inline and its output is shown.

## Test cases

- **TC1 —** the assembled prompt is persona, then the facts block, then the handoff note if
  one is pending, in that order, with the sizes and total reported.
- **TC2 —** a consumed handoff note (only `handoff-last.md` present) is reported as consumed,
  not as part of the prompt.
- **TC3 —** a file changed after the session started is listed as needing a restart; one
  changed before it is not; an unreadable file is not reported as fresh.
- **TC4 —** a scenario row carries its prompt files' sizes and its unit's schedule; a missing
  prompt file is named as missing rather than skipped.
- **TC5 —** running a scenario the config does not name does nothing and says so — the name
  arrives from a form.
- **TC6 —** a long scenario is started detached (`systemd-run`), a dry run is not.
- **TC7 —** both screens leave `SOON`, answer with their sections, and escape everything
  interpolated.
- **TC8 —** the prompt screen never prints a key: it shows the same facts the prompt carries,
  and nothing from `.env*`.
