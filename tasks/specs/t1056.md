# t1056 — panel probes always render stale: stamp `checked` from the cache mtime

Found by the phase-1 panel review (M1 in
`status/state/code-review/2026-10-31-panel-phase1-scan.md`).

## Problem / goal

`panel/data.py::probe_rows()` computes a probe's age from `p["checked"]` or `p["ts"]`, but
no probe JSON carries either field — all eleven `status/cache/*.json` files hold only `id`,
`ok`, `severity`, `text`, `value`, `ttl`. `status/run.sh` keys its own TTL logic off the
cache file's **mtime**. So on the real system `age` is always `None`, every row is `stale`,
and the live panel shows «невідомо коли / застаріле» on every probe forever — the
age-against-TTL display never works.

Fix at the gathering boundary: `probes_now()` stamps each parsed probe with a tz-aware UTC
`checked` taken from the mtime of its cache file (`status/cache/<id, ":" → "-">.json`) —
the same clock run.sh trusts. A probe whose cache file is missing stays unstamped and
correctly renders as stale (unknown age is not freshness, t1055 TC1).

## Test cases

- **TC1 — regression:** `probes_now()` (with `subprocess.run` stubbed to return two probes
  and a cache dir holding a file for the first, mtime set 10 minutes ago) returns the first
  probe with a `checked` whose age against now is ~600 s, and `probe_rows()` on that output
  marks a probe inside its TTL fresh. Fails before the change (no `checked`, always stale).
- **TC2 — missing cache file:** a probe with no cache file comes back without `checked` and
  still renders stale.
- **TC3 — id with a colon:** probe id `news:світ` maps to cache file `news-світ.json`.

## Approach

`probes_now()` gains a `cache_dir` parameter (default `status/cache`) for testability; after
parsing run.sh's JSON it sets `p["checked"] = <mtime as UTC isoformat>` for probes that do
not already carry one. `probe_rows()` stays pure and untouched. Out of scope: defaulting a
missing `ttl` (run.sh assumes 300 where the panel assumes 0 — all current probes carry one).
