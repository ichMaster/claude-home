# t1055 — admin panel, phase 1: the shell and the Pulse screen

Phase 1 of `t1037` (`docs/features/ADMIN-PANEL.md` § Phases).

## Problem / goal

"Is it alive and did anything happen" currently costs an SSH session and four commands:
`status/run.sh`, `systemctl --user list-timers`, a look at two state files, and a tail of
the change log. Phase 1 puts that on one page and builds the shell the other nine screens
will hang from.

Scope is deliberately read-only: no form, no button that changes anything. The panel has to
prove it reads the system correctly before it is allowed to write to it.

## What it is

- `panel/` — one package: `data.py` (collectors, pure where it can be), `render.py` (HTML),
  `server.py` (routing, stdlib `http.server`), `static/panel.css`.
- Listens on `127.0.0.1:8091` (`panel.host` / `panel.port`), reached over an SSH tunnel.
  No authentication, by design — it is not exposed.
- `panel/noos-panel.service`, a user unit kept in the repo and installed from it, so the
  unit is version-controlled even though systemd reads it from `~/.config/systemd/user/`.
- The Pulse screen: probes, timers, queues, recent changes. Refreshes itself.

## Test cases

- **TC1 — probe staleness.** `probe_rows()` marks a probe whose cached answer is older than
  its own TTL as stale, and one inside its TTL as fresh. An answer with no timestamp is
  stale rather than silently fresh, because unknown age is not freshness.
- **TC2 — severity drives the dot, nothing else.** A row's mark comes from `severity`
  (`alert` / `warn` / `info` / `quiet`) and an unknown severity falls back to the neutral
  dot rather than raising.
- **TC3 — timer rows from `systemctl show`.** `timer_rows()` reads the key=value output for
  a timer and its service and yields unit, next run, last run, and whether the last run
  succeeded. A timer whose service never ran reports "не запускався", not a crash; a missing
  or unreadable property block yields a row with blanks, never an exception.
- **TC4 — queues.** `queues()` reports the YouTube pending count, the mail last UID and the
  non-`info` watcher signatures, and returns zeroes with no state files present (a fresh
  machine is not an error).
- **TC5 — change log tail.** `recent_changes(n)` returns the newest n records newest-first
  across day files, skips a torn JSONL line, and returns `[]` when the directory is empty.
- **TC6 — rendering.** `render_pulse()` escapes text coming from probe output and the change
  log (a probe's text is machine-made but a mail subject reaches it, and a subject is
  attacker-controlled), emits one row per probe, and is valid enough that the page contains
  every section heading.
- **TC7 — routing.** `/` serves Pulse, `/static/panel.css` serves the stylesheet with
  `text/css`, an unknown path is 404, and a path with `..` cannot escape `panel/static`.

## Approach

Collectors are plain functions over data passed in, so tests never shell out: `server.py`
gathers (running `status/run.sh`, `systemctl show`, reading state files) and hands the
result to pure functions. The one collector that must shell out in a test is stubbed at the
`subprocess.run` boundary.

Rendering is f-strings with `html.escape` on every interpolated value — no template engine,
no build step, matching the spec's "works on a machine with no internet".

Auto-refresh is a `<meta http-equiv="refresh">` at `panel.refresh_sec` (30). Fragment swaps
come later, when there is something interactive to swap; a meta refresh on a read-only board
costs nothing and cannot break.

Out of scope for this phase: every other screen, any write, authentication, mobile layout
beyond "Pulse is readable on a phone".
