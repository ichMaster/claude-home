# t1039 — video relevance was decided by a regex, not the LLM

## Problem

`search.py videos()` scored each subscription video by word overlap with the query and kept
only those above `search_min_score`. A video whose title did not literally share the query's
words was dropped before Bruno ever saw it — so the owner's pointed-to video went missing. The
owner's standing rule: matching is the LLM's job, not a script (2026-10-31, repeated).

## Test cases

- **TC1 —** `videos("anything")` returns candidates ranked by recency, never filtered by the
  query string (the query does not change which rows come back).
- **TC2 —** the candidate pool is capped at `telegram.inbox.search_video_pool`.
- **TC3 —** Bruno's answer, given a pool containing an on-topic video with non-overlapping
  title words, still surfaces it (LLM relevance). Manual check.

## Approach

`videos()` drops all scoring and returns the most recent `search_video_pool` (500) archive
rows. Relevance is decided downstream by Bruno reading the titles; `bruno.md` instructs it to
match by meaning, not word overlap, and to say so when nothing fits. Removed `score()`,
`words()`, `STOP`, and the `search_min_score` config.
