# t1080 — admin panel, phase 7: Memory and Sources, with file versioning

Phase 7 of `t1037`, screens 6 and 7. Phase 5 stays deferred.

## Problem / goal

Two screens, and one thing that had to be built with them.

**The screens.** Facts and channels are lists, which is the thing a chat is worst at. One
answer in particular exists nowhere else today: *which pinned facts did not fit the
prompt*. The session wakes with the top `memory.max_facts_in_prompt` of them and the rest
are stored and silent; finding out which means counting by hand.

**The versioning.** The owner's point (2026-11-01): an atomic write protects against a
write cut in half, not against a correct write of the wrong content, an `rm`, or a dead
disk — and these files are not in git. This screen is the first that lets a button edit
`config.local.json`, the file holding birth data, the calendar id, the voices and the 603
channels, with no copy anywhere. Building the edit without the safety net would be
building the hazard.

## The versioning, as agreed and corrected

His idea was: when a file is replaced, keep a copy; add a retention policy. Three
corrections, all discussed before building (2026-11-01):

1. **Not every rewritten file.** `status/state/youtube.json` is 68 KB rewritten each poll
   with a new cursor and timestamp; the bots' state is 24 KB every two minutes. Versioning
   those is ten megabytes a day of copied cursors, burying the one config this exists to
   protect. `versions.files` lists what hurts to lose; caches and cursors are deliberately
   absent because they rebuild themselves.
2. **Nothing is written when nothing changed.** Most rewrites are identical to what is on
   disk. The copy is keyed by content hash, so a version appears only where something
   actually became different.
3. **A version is useless without a way back.** `tools/versions.py list | diff | restore`.
   Restoring goes through the same atomic write, so the file it replaces becomes a version
   too and an undo can be undone.

Retention by age, encryption and a copy off this machine are **phase 10**, at his
instruction. These copies sit on the same disk and protect against a wrong write, not
against losing the disk; `versions.keep` is a safety belt against a runaway writer, not a
policy.

Append-only files get a daily copy instead of versioning — there is no rewrite to hang one
on. `tools/versions.py snapshot` runs from the nightly changes timer.

## Test cases

- **TC1** — a rewrite of a precious file keeps the previous content; a rewrite of a cache
  keeps nothing.
- **TC2** — five identical rewrites make one version; the next version appears only when
  the content changes again.
- **TC3** — the cap keeps the newest N and drops the oldest.
- **TC4** — a failure inside versioning never costs the write it was protecting.
- **TC5** — `diff` and `restore` round-trip, and the restore is itself reversible.
- **TC6** — the copy carries the original's mode (`config.local.json` is 600).
- **TC7** — facts split into what reaches the prompt and what was cut, in the same order
  `facts.prompt()` uses; unpinned are separate from cut; both limits are reported.
- **TC8** — the archive reports its size and freshness, and says so plainly when absent.
- **TC9** — channels carry their last video from the archive; quiet ones sort last.
- **TC10** — the filter test box classifies exactly as the mail probe would, important
  outranking noise.
- **TC11** — disabling a channel or starring it rewrites `config.local.json` without
  touching unrelated keys and keeps mode 600; an unknown channel changes nothing.
- **TC12** — every free text is escaped; every form carries the token.

## Deliberately not done

- **"Remove dead channels"** — it means 603 HTTP requests to find the 404s, which is a job
  for a probe with a rate limit, not a button that holds a page open. Its own task.
- **Hybrid archive search.** The screen does FTS only and says so: the embedding model is
  240 MB and loading it inside a request would make the page take half a minute.
- **Editing the topic files** — that is the prompt-editing shape of phase 5.
