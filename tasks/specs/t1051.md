# t1051 — mood.py: three defects in the forecast pipeline

## Problem / goal

1. **yesterday_block empty after --resume.** A `--resume` run appends a log block holding
   only `--- підсумок (перероблено) ---`. The next morning `yesterday_block` reads the LAST
   block before today and its regex `--- (?:підсумок|прогноз) ---` cannot match the reworked
   marker, so it returns "" — the draft/review/summary silently lose yesterday's context,
   exactly the continuity the owner asked for.
2. **A failed call in stages 3–5 discards everything.** `weigh`, draft, review and summary
   have no error handling, and `log_run` only fires after full success. One transient
   claude-CLI failure at the weighing stage throws away the ~14 completed interpretation
   calls (7–9 minutes), writes nothing to the log, and `--resume` has no draft to resume
   from.
3. **The owner's natal portrait leaks into another subject's forecast.** For `--subject X`
   with no `natal_file` configured, `astro.subject_conf` falls back to `astro.natal_file` —
   the owner's written portrait — which is then appended to X's computed chart, contaminating
   the reading and violating the documented one-chart-never-leaks isolation.

## Test cases

- **TC1 (regression)** — a log whose newest pre-today block carries only
  `підсумок (перероблено)`: `yesterday_block` returns that reworked summary, not "".
- **TC2 (regression)** — `write_forecast` whose review call raises still leaves the produced
  draft in the caller's `partial` dict, so it can be logged and resumed.
- **TC3 (regression)** — with `astro.SUBJECT` set and no subject `natal_file`, `natal_text`
  returns the computed chart only — no owner portrait; with no subject the portrait still
  appends.

## Approach

(1) Accept `підсумок (перероблено)` in the regex and walk previous blocks newest-first until
a summary is found. (2) `write_forecast` records draft/review into an optional `partial`
dict as they are produced; `main` wraps stages 3–5 and on failure appends `partial` to the
log before re-raising (the unit still fails loudly; nothing is sent). (3) `natal_text` reads
the portrait path for a named subject only from that subject's own config, never the owner's
fallback.
