# t1098 — panel: phase 9 becomes the log of what was sent

The owner's decision, 2026-11-01, reversing his own request of 2026-10-31 (the chat screen)
after reading the argument against it.

## Problem / goal

Phase 9 was a chat screen: a box that posts into the main Telegram chat through the Bot API,
with the thread read back from a log `notify.sh` would write. Two things are wrong with it:

- **He listens, he does not read.** Every reply he receives is voice plus text, and the panel
  renders no voice. So the box duplicates a channel that already works better.
- **It would be the only screen that writes outward**, on a port bound to the whole local
  network with no authentication. Phase 8's High finding had just shown what that port
  really means. A message arriving in the main chat is treated as the owner's, so a send box
  there is an unsigned way to instruct the session.

What is worth keeping is the half underneath it: **nothing in this system records what it
actually said.** The digest, the forecast, the reminders and the probe reports leave through
`notify.sh` and vanish. A timer that ran successfully and said nothing is indistinguishable,
in `systemctl` and in the journal, from one that did its job.

## The change

Documentation only — this task rewrites the plan, it builds nothing:

- `docs/features/ADMIN-PANEL.md`: screen 11 is **Надіслане** (Sent), read-only, no send box;
  phase 9 is the log plus that screen, with the body of a message behind a switch
  (`panel.sent_bodies`, default off) for the same reason t1094 withheld journal bodies — the
  text of a digest *is* the owner's calendar and mail.
- `docs/ROADMAP.md`: v5.4 Rules is recorded as reading-only and done; v5.5 as done, with the
  refused drag noted; **v5.6 Sent** replaces the chat window; **v5.7 Editing** is new and
  blocked on authentication. The "deliberately not doing" entry about a chat window is
  restored with the dates of both decisions, and the authentication entry now says plainly
  that it is what v5.7 waits on.
