# t1040 — daily check for new YouTube subscriptions

## Problem / goal

The owner wants a daily check for channels he newly subscribed to, so Bruno's search covers
them without a manual Takeout re-export (2026-10-31). The subscription **list** currently only
updates by hand.

## The hard constraint

YouTube exposes a user's own subscriptions only through the Data API `subscriptions.list` with
**OAuth** (`youtube.readonly`). There is no key-only or RSS path — a plain API key cannot read
a private subscription list. So automatic detection requires a one-time browser login by the
owner to mint a refresh token; the session cannot complete OAuth on its own.

## Approach

1. One-time, by the owner in the terminal: create an OAuth client (Desktop) in Google Cloud,
   run a small helper that opens the consent screen and stores a refresh token in `.env`
   (mode 600, git-ignored).
2. Daily job (`noos-subs.timer`): `subscriptions.list` → current channel set, diff against the
   603 in `config.local.json` (`probes.youtube.channels`), report any additions in the morning
   and append them to the polling list so the archive starts covering them.

## Test cases

- **TC1 —** diff logic: given a stored set and a fetched set with one extra channel, the job
  reports exactly that one as new (pure function, testable without OAuth).
- **TC2 —** a removed channel is noted but not deleted from polling (subscriptions you dropped
  may still have videos worth the archive); reported as "no longer subscribed".
- **TC3 —** OAuth/network failure → the job reports it and changes nothing, never wipes the
  list.
