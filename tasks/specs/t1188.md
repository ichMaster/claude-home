# t1188 — a long-lived token keeps Noos alive when the Claude login expires

## Problem / goal

The CLI login (`~/.claude/.credentials.json`) carries a refresh token with a hard expiry of a
few weeks. On 2026-11-14 at 08:20 it ran out, and from then on the always-on session and every
headless `claude -p` run failed with `Login expired` until the owner ran `/login` by hand the
next afternoon. t1187 made that outage loud; this task makes it survivable.

`claude setup-token` issues a one-year token (`CLAUDE_CODE_OAUTH_TOKEN`), but it is
inference-only: measured on 2026-11-15, a headless run with it saw **no** claude.ai connectors
(Gmail, Calendar, Drive, Notion, Docs), while the same run on the regular login saw all five.
Remote Control needs the full login too. So the token cannot replace the login — only stand in
when the login is gone, and the owner must still be told to `/login` to get the rest back.

## Test cases

- **TC1 —** credentials with a refresh token expiring in the future → login alive, no fallback:
  `env()` does not set `CLAUDE_CODE_OAUTH_TOKEN`, `fallback_file()` returns `None`.
- **TC2 —** credentials whose refresh token expired (or is empty, or the file is missing) and a
  fallback file holding a token → `env()` sets `CLAUDE_CODE_OAUTH_TOKEN` to it and
  `fallback_file()` returns the file's path.
- **TC3 — edge:** login dead and no fallback file (or an empty one) → nothing is set; nothing
  crashes.
- **TC4 — edge:** a `CLAUDE_CODE_OAUTH_TOKEN` already in the environment is left untouched.
- **TC5 —** the `auth` probe warns when the login expires within `probes.auth.warn_days` and
  when the session is running on the fallback, naming `/login` in the text and with no Latin
  script in the spoken copy; a healthy login far from expiry stays `info`.
- **TC6 —** the token value never appears in any probe text or CLI output.

## Approach

`status/tools/claude_auth.py` decides from the credentials file alone (no network): the login
is alive while the refresh token exists and expires later than `probes.auth.margin_min` from
now. Python callers of `claude -p` (`mood.py`, `memory/handoff.py`, `status/bots/inbox.py`)
pass `env=claude_auth.env()`; shell callers (`start.sh`, the four `*-headless.sh`) source
`status/tools/claude-auth.sh`, which sources the fallback file only when
`claude_auth.py fallback-file` names it. `start.sh` re-decides before every launch of the loop.

The `auth` probe gains the expiry check, so the owner hears about a dying login days before it
dies instead of after.

Out of scope: refreshing the login automatically (it needs a browser), and switching the
session back from the fallback without a restart — the nightly 05:00 restart does that.
