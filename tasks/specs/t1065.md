# t1065 — panel: a torn review report 500s the whole /changes page

Fix from the phase-2 review (`status/state/code-review/2026-10-31-panel-phase2-scan.md`, M3).

## Problem / goal

The nightly review and the committing session write the report files (Ukrainian,
multi-byte UTF-8) while the panel may be reading them. A read landing mid-character
raises `UnicodeDecodeError`, which is not an `OSError`: `review_nights()` catches only
`OSError`, and `commit_detail()` reads the commit-review file with no handling at all.
Constructed: a report truncated one byte into «Б» raises out of both functions, the
handler's catch-all turns it into a 500, and the entire screen is gone because one file
was torn.

## Test cases

- **TC1 (regression)** — `review_nights()` over a directory holding a scan file truncated
  mid-multibyte-character does not raise and still returns the night. Fails before.
- **TC2 (regression)** — `commit_detail()` with a commit-review file truncated the same
  way does not raise; the reading is still reported as present. Fails before.
- **TC3** — `commit_detail()` with an unreadable (OSError) review file does not raise and
  reports the reading as absent rather than inventing content.

## Approach

Read the three file kinds (`review_nights` reports, the commit-review file, the test files
scanned for a task id) with `errors="replace"` — a torn tail costs one replacement
character, not the page — and guard the commit-review read with the same `OSError` catch
the others already have. Out of scope: file locking; the writers stay untouched.
