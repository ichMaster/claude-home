# t1120 — a test fixture reproduced a real line out of the owner's calendar

Caught by my own pre-push reading of `git diff origin/main..HEAD`, 2026-11-01, before the
push.

## Problem

`tests/test_sent.py` asserted that a message body does not reach the HTML with
`panel.sent_bodies` off, and the string it used was modelled on the line the phase-8 review
had extracted from the live journal: a wake at noon and a birthday at 17:00. Two real
appointments of 31.10, with the names stripped.

The commit reading for 79a0d25 called that fixture "not a real calendar line", which was
wrong on re-reading: the shape and the content are his, and the repository is public. It also
concerns a third party — someone died — which is not the owner's to publish either.

The test's purpose is served by any string that looks like a calendar line, so the real one
bought nothing.

## Fix

An invented line of the same shape: a car inspection and a dinner. The comment says why,
so the next person does not "improve" it back toward realism.

## Test cases

- **TC1 —** the existing body-hiding test still passes against the new fixture.
- **TC2 —** no copy of the original string remains in anything committed (`grep` over
  `tests/`, `tasks/specs/`, `docs/` and the root `*.md`). The review report that quotes the
  genuine line stays under the git-ignored `status/state/`.

## Done when

- [x] fixture replaced, suite green
- [x] committed referencing t1120, before the push

## What this changes about the process

A commit reading has to treat "it is only a test fixture" as a claim to check, not a reason
to stop looking. A fixture written to imitate sensitive data is the one place where realism
is a defect.
