# t1253 — mood2 check_items tolerates JSON null without flagging or aborting

## Problem / goal

`status/mood2/read.md` line 50 instructs the model: «Якщо чогось у тексті немає — null
або нуль», so a position with `"meaning": null`, `"natal": null`, `"flag": null` or
`"weight": null` is a prompt-compliant answer. `check_items` handles none of them:

- `str(item.get("meaning", "")).strip()` turns `None` into the non-empty string
  `"None"`, so «порожнє трактування» never fires — a window with no interpretation
  enters the pipeline silently, the exact fidelity loss `Unfaithful` exists to stop.
- Same hole for a natal item with `"natal": null`: «натальна позиція без планети»
  passes, and `mandatory_ids()` then forces a natal block with no planet named into the
  reading.
- Conversely `"flag": null` renders as «невідомий знак «None»» and `"weight": null` as
  «вага «None» поза межами» — and since the read stage has no retry, a prompt-compliant
  answer aborts the whole 08:15 morning (exit 3, only the failure notice goes out).

The asymmetry is the fix: null in a *content* field is emptiness and must be flagged
exactly like `""`; null in `flag`/`weight` means "none" per the prompt and must
normalise to `""`/`0` without a problem.

## Test cases

- **TC1 —** given a non-natal item with `meaning: None`, `check_items` reports
  «порожнє трактування» (regression: passes silently before the fix).
- **TC2 —** given a natal item with `natal: None`, `check_items` reports
  «без планети» (regression: passes silently before the fix).
- **TC3 —** given an item with `flag: None`, `check_items` reports no problem
  (regression: «невідомий знак «None»» before the fix).
- **TC4 —** given an item with `weight: None`, `check_items` reports no problem —
  null weight reads as zero per read.md (regression: «вага поза межами» before).

## Approach

Normalise with the `or` idiom `check_reading` already uses (mood2.py:811-812):
`item.get("meaning") or ""`, `item.get("natal") or ""`, `item.get("flag") or ""`,
`item.get("weight") or 0`. Nothing else changes; `weight_of()` already tolerates None.
