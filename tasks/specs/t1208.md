# t1208 — services probe dies without JSON when docker is down

## Problem / goal

`status/probes/services.sh` runs under `set -euo pipefail`. The tmux/systemd checks on
lines 4-6 are guarded with `&& echo 1 || echo 0`, but the docker assignments are not:
with the docker daemon stopped or the socket unreadable, `docker ps` exits non-zero,
pipefail propagates it through `| wc -l`, and errexit kills the script before the JSON
printer runs. `run.sh` then substitutes the generic fallback «Пробник services не
відповів» (constant signature, one-shot warn) — so while docker is down, the repeating
`alert` for a dead tmux session can never be emitted, and the docker outage itself is
never named. The main always-on-session watchdog is silenced by an unrelated failure.
Found by the nightly self-review of 2026-11-19 (Medium).

## Test cases

- **TC1 —** given a PATH where `docker` exits non-zero and tmux/systemctl answer healthy,
  when `services.sh` runs, then it exits 0 and prints valid probe JSON naming the docker
  failure with severity `warn`. (regression — fails before the change: no output, exit 1)
- **TC2 —** given the same dead docker and a dead tmux session, then the JSON still
  carries severity `alert` for the tmux failure.
- **TC3 — edge:** with everything healthy (stub docker listing two containers, none
  exited), the output is byte-identical in shape to before: ok=true, severity info,
  containers counted.

## Approach

Wrap the two docker assignments in an `if` condition (errexit does not apply there;
pipefail still yields false on docker failure), set `docker_ok=0`, `cnt=0`, `down=""` on
failure, pass `docker_ok` into the python printer, and add «docker не відповідає» to the
bad list. Severity logic unchanged: tmux dead → alert, anything bad → warn.
