# t1079 — run_script returns an OSError as a failure, never raises it

Found by the phase-6 review (04c09b7, finding M4 in
`status/state/code-review/2026-10-31-panel-phase6-scan.md`).

## Problem

`run_script` catches `subprocess.SubprocessError` only, but `subprocess.run` raises plain
`OSError` when the exec itself fails: `E2BIG` for an oversized argument (the panel admits
1 MB of form body while execve caps one argument at ~128 KB — verified with a 300 KB
argument), `FileNotFoundError` if the interpreter path is wrong. Those escape to the
handler's generic 500 («panel error, see the log») instead of a message on the page —
against the function's own contract: "a failure is returned, never swallowed".

Failure: paste a very large text into the add box → bare 500 instead of the board saying
what went wrong. Same for every other run_script caller (zirka actions).

## Fix

Catch `(OSError, subprocess.SubprocessError)` and return the failure, as the docstring
promises. One line.

## Test cases

- **TC1** — `subprocess.run` raising OSError makes `run_script` return
  `(False, "не вдалося запустити: …")`. (Fails before the fix: raises.)
- **TC2** — the existing timeout behavior is unchanged (`SubprocessError` subclasses
  still caught; covered by TC1's except tuple plus the suite staying green).
