# t1235 — the panel's Zirka recalc button still launches the stopped v1 pipeline

## Problem / goal

The owner presses «перерахувати день» on the panel's Zirka screen.
`zirka_action('recalc')` (panel/server.py:557) systemd-runs `status/mood.py --day <day>`
with no flags — the full v1 pipeline, stopped by the owner's order since 2026-11-12. It
sends BOTH v1 messages (biorhythms and a v1 ephemeris reading, not the astrologer's
calendar) to the mood bot and overwrites mood.json and forecast-claims — a deprecated
pipeline's reading presented as the day's forecast, diverging from the morning's real v2
one. This is exactly the t1214 defect; that fix was applied only to inbox.py's
`recompute_forecast()`, and tests covered only that path.

## Test cases

- **TC1 — regression:** `zirka_action({"action": ["recalc"], "day": [...]})` launches
  `mood2.py --day <day> --send`, not `mood.py`. Fails before the change.
- **TC2 —** the systemd-run envelope survives: fixed unit name from
  `astro.recalc_unit` (the in-flight lock), `--user`, `--collect`.
- **TC3 — edge:** a unit-exists failure still answers «Перерахунок уже йде.»

## Approach

Point the recalc command at `mood2.py --day <day> --send`, mirroring inbox.py's t1214
fix, and soften the reply («за кілька хвилин» — v2 is not an eight-minute pipeline).
Nothing else on the screen changes.
