# t1050 — remind.py: a torn reminders.json permanently stops all nudges

## Problem / goal

`status/remind.py` rewrites `reminders.json` every 5 minutes with a plain `write_text` and
reads it back with an unguarded `json.loads`. A crash or power cut mid-write (regular outages
here) leaves truncated JSON; every subsequent run raises before reaching the rewrite, so no
reminder is ever sent again until the file is deleted by hand.

## Test cases

- **TC1 (regression)** — given a truncated `reminders.json`, a run completes and leaves valid
  state on disk instead of raising.
- **TC2** — dedup still works: a lead nudge already recorded in state is not re-sent.

## Approach

Guard the read (fall back to `{}` — losing two days of dedup memory at worst repeats a nudge
once, which beats never nudging again), write via `noosconf.atomic_write_text`, wrap the body
in `main()` for testability. The Low findings here (tz handling, the sleep-window config
keys, fact-kind events) stay as reported.
