# t1127 — log-section consumers left behind by the t1126 rename

## Problem / goal

The t1126 rebuild renamed the mood-log sections (`підсумок`/`прогноз` → `вибір`/`письмо`/
`перевірка`) and the reading's blocks (`КОРОТКО`/`ПІДСУМОК`/… → `ДЕНЬ`/`ПРОГНОЗ`/`ДІЯ`/
`ДУГА`/`ОСНОВА`). Four consumers still parse the old names, so they silently stopped seeing
any reading written since 2026-11-01:

1. **High** — `status/mood_feedback.py:97 forecast_of()` looks for
   `підсумок (перероблено)`/`підсумок`/`прогноз`, none of which exist any more, so
   `calibrate()` always exits at «немає прогнозу» — with a no-op `note` in the 08:15 run,
   completely silently. The calibration loop the rebuild was built around is dead.
2. **Medium** — `status/astro_learn.py:184 ours()` requires the literal `--- підсумок ---`,
   so reference learning loses the РОЗХОДЖЕННЯ comparison for every new day.
3. **Medium** — `status/mood.py:263 yesterday_block()` matches only the old section names and
   requires a `ПІДСУМОК` block, so the УЧОРА context is pinned to the last old-format day
   (2026-11-01) and goes empty once the log rotates past it.
4. **Medium** — `panel/zirka.py` (`BUDGETS`, `day_runs` summary) parses the old shape, so
   /zirka shows «блок відсутній» five times for a day with complete runs and never checks
   the real `astro.budget_chars` budget.

## Test cases

- **TC1 —** given a new-format log (`--- письмо ---` with ДЕНЬ/ПРОГНОЗ/ДІЯ/ДУГА/ОСНОВА),
  `mood_feedback.forecast_of(day)` returns the reading (fails before the change).
- **TC2 —** given the same log plus a newer `--- письмо (перероблено) ---` block,
  `forecast_of` prefers the resumed text; an old-format log still works (legacy names).
- **TC3 —** `astro_learn.ours(day)` returns the new-format reading, and the resumed text
  when one exists.
- **TC4 —** `mood.yesterday_block(day+1)` over a new-format log returns a non-empty note
  built from ДЕНЬ/ПРОГНОЗ/ДУГА; the old-format log keeps working (existing TC stays green).
- **TC5 —** `zirka.day_runs` finds the summary of a new-format run (the `письмо` stage), and
  `zirka.reading_blocks` on a new-format reading measures ДЕНЬ/ПРОГНОЗ/ДІЯ/ДУГА/ОСНОВА and
  flags the spoken total against `astro.budget_chars`; the old five-block shape still renders.

## Approach

One precedence chain in one place: `mood.final_reading(day)` — `письмо (перероблено)` →
`письмо` → `підсумок (перероблено)` → `підсумок` → `прогноз` (newest run first via
`logged_sections`). `forecast_of` and `ours` delegate to it. `yesterday_block` extends its
regex with the new names and builds the note from ДЕНЬ/ПРОГНОЗ/ДУГА when ПІДСУМОК is absent.
`zirka.reading_blocks` detects which block family the summary uses: the new one is measured
per block with the spoken total against `astro.budget_chars`, the legacy one keeps its
per-block budgets; `day_runs` picks the summary by the same precedence as `final_reading`.
`render._blocks_table` learns to print a row with no per-block budget.

Deliberately out of scope: `перевірка` is never used as the reading (it holds the raw check
output with ОЦІНКА, not the sent text); compress.md drift is a separate Low finding.
