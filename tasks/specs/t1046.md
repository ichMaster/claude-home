# t1046 — watch.py: corrupt state kills the watcher; a failed send is never retried

## Problem / goal

1. `json.loads(STATE.read_text())` is unguarded and the state is rewritten every 15 minutes
   with a plain `write_text`. A kill mid-write leaves torn JSON, and every subsequent run of
   the watcher raises before checking a single probe — air-raid and outage alerts stop
   silently until the file is deleted by hand.
2. `newstate` (new signature, `sent=now`) is persisted at line 70, *before* `notify.sh` runs
   at line 79 with its exit code ignored. A warn item (a new outage schedule) whose send
   fails — plausible exactly when the power is out — is recorded as delivered; warn only
   re-sends on signature change, so that notification is lost.

## Test cases

- **TC1 (regression)** — given a truncated `watch.json`, a run with a warn probe does not
  crash and ends with valid state on disk.
- **TC2 (regression)** — given a new warn signature and `notify.sh` exiting non-zero, the new
  signature is NOT persisted, so the next run re-detects the change and retries the send.
- **TC3** — same warn with `notify.sh` exiting 0: the signature is persisted and a second run
  with the same data sends nothing.

## Approach

Guard the state read (fall back to `{}`), write via `noosconf.atomic_write_text`, and move
the state write after the notify call, keeping the old state when the send fails. Body
wrapped in `main()` for testability.
