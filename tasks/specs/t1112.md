# t1112 — four Mediums from the full review: CRLF, a missing redirect, a raising level, and a form that could weaken the login

Found by the full review, 2026-11-01 (writes M2, M4, M5 and security M5).

## Problems and fixes

**The editor rewrote the files in CRLF** (writes M2). A browser normalises a `<textarea>`'s
newlines, so one save of `persona.md` changed all 71 lines and one save of `CLAUDE.md` all
1 300. The cost lands on the rule this project puts most weight on: the commit-time security
reading is a human reading of `git diff --cached`, and after a panel save that diff is the
whole file. `save_file` normalises to `\n`.

**`POST /zirka` was the one write without a redirect** (writes M5). An F5 re-sent the evening
question, re-ran the eight-minute forecast, or added the same reference again together with
the calibration rules it produces. It now redirects like every other write, carrying the day
and the message in the query.

**A malformed permission level raised instead of failing closed** (writes M4). `got in LEVELS`
needs a hashable value, so a JSON array or object raised `TypeError` — and all three readers
catch broadly, so the **entire permission block silently vanished from the system prompt**
while both screens that show it looked normal. The level is now compared as a string, and a
`permissions` node that is not a block reads as no overrides.

**The settings form could weaken the panel's own protections** (security M5). From the page
those settings protect it could raise `panel.auth.max_attempts`, shorten `lock_min`, stretch
`ttl_hours`, set `panel.journal_scope=full` and re-open the disclosure t1094 closed, move
`versions.dir` so no copy is kept, lower `panel.edit_min_ratio` past the shrink guard, or
rebind `panel.host`. All of those now refuse with "this protects the panel — terminal only",
and the refusal is checked **before** the key lookup, so a protected key says so rather than
«такого ключа немає».
