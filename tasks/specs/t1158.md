# t1158 — mood2 read-stage item without id crashes the timer run

## Problem / goal

`check_items` validates duplicates, kinds, meanings and weights, but never that each item is
a dict carrying a non-empty `"id"`. A read stage that returns one otherwise-valid item with
the `id` missing passes the check, and the pick stage then dies on `known = {i["id"]: i for i
in items}` with a raw `KeyError: 'id'` (likewise `blocks()`); a non-dict element (a stray
string in the model's JSON list) raises `AttributeError` inside `check_items` itself. Neither
is among the named errors `main()` catches, so the 08:15 `noos-mood2.service` run dies with a
traceback and exit 1 — the exact failure mode the fidelity check exists to turn into a clean
«розбір не збігається з еталоном» stop.

Found by the nightly code review, 2026-11-12 (scan report, Medium #1); reproduced by the
adversarial verifier.

## Test cases

- **TC1 —** given an item list where one item lacks `"id"`, `check_items` returns a problem
  naming it instead of `[]` (regression: before the fix it returns `[]` and the pick stage
  crashes).
- **TC2 —** given a list containing a non-dict element, `check_items` returns a problem
  instead of raising `AttributeError` (regression).
- **TC3 —** the valid fixture still passes with no problems.

## Approach

A shape gate at the top of `check_items`, right after the empty/non-list check: any element
that is not a dict or has an empty `id` fails the whole parse immediately (the rest of the
counting assumes dicts keyed by id). `run()` already turns problems into `Unfaithful` →
exit 3, which the retry/report path handles.
