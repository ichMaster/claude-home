# t1036 — Zirka can't read a large reference sent as a file

## Problem

A long astrologer reference pasted into Zirka's chat arrives from Telegram as a **document**
(`.txt`), not as message text — the client turns a big paste into a file. `inbox.py` only read
`text`/`caption`/`voice`, so the update was dropped as «без тексту» and the reference never
reached the learning pipeline (observed 2026-10-31 in `status/state/bots/dropped.jsonl`).

## Test cases

- **TC1 —** a message with a `document` of mime `text/plain` under the size cap → its bytes are
  read and returned as the message text (regression).
- **TC2 —** a `document` over `telegram.inbox.max_document_bytes` → ignored (returns empty),
  so a huge file cannot blow up memory.
- **TC3 —** a non-text document (e.g. `image/png`) → ignored.

## Approach

`read_document()` downloads the file via `getFile` when the document is texty (mime `text/*`
or a `.txt/.md/.csv/.log` name) and within the size cap, decodes utf-8. The poll loop calls it
after the text and voice checks. Size cap in `config.json` → `telegram.inbox.max_document_bytes`.
