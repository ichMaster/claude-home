# t1217 — read_document transient failures raise instead of returning empty

## Problem / goal

t1213 (e549d23) made handle_update catch exceptions from `read_document` and say the loss
out loud. But inside `read_document` the two transient failure legs still return `""`
instead of raising: `getFile` answering `{"ok": false}` (status/bots/inbox.py:217-218) and
any exception during the file download (the bare `except` around `urlopen`,
inbox.py:220-224). So a download timeout or a transient 5xx on the file URL never reaches
the t1213 guard: with a caption the message is answered as caption-only, without one it
drops as «без тексту» — the offset commits, the reference body is consumed forever, and no
«Документ не прочитався» goes out. The exact silent loss t1213 was opened for, one HTTP
call later.

## Test cases

- **TC1 —** given `getFile` succeeds but the download `urlopen` raises, when
  `handle_update` processes a document message, then the «документ не прочитався» notice is
  sent and `answer()` never runs (regression — fails before the change).
- **TC2 —** given `getFile` returns `{"ok": false}`, then `read_document` raises instead of
  returning `""`.
- **TC3 — edge:** the deliberate refusals (size cap, binary mime) keep returning without a
  crash — they are t1218's subject, not this one's.

## Approach

In `read_document`: raise `RuntimeError` when `getFile` answers not-ok; delete the
try/except around the download `urlopen` so the exception propagates to the t1213 guard in
`handle_update`. Nothing else changes.
