# t1199 — headless mood model calls run with no tools

## Problem / goal

`mood.run_claude()` passes no `--allowedTools ""`, unlike `status/bots/inbox.py` which
disables tools explicitly. No settings file denies tools either, so every pipeline stage —
including the ones whose prompt embeds the forwarded astrologer's text (`read`, `wide`,
`learn`), which is untrusted input from a Telegram chat — runs with Read/Grep/Glob available
and needs no approval to use them, with cwd at the repo root holding `.env.telegram`,
`.env.voice`, `.env.gmail`, `.env.panel`. An injected instruction in a forwarded text could
have the call read a secret and embed it in a `meaning`/`ПРАВИЛО` field, which then lands in
state files the panel surfaces. CLAUDE.md states these text-transformation calls are supposed
to be tool-free, and every caller of `run_claude` (mood stages, mood2 stages, astro_learn) is
a pure text transformation that needs no tool. Found by the nightly review of 2026-11-17
(Medium, security).

## Test cases

- **TC1 — regression:** the command `run_claude` builds contains `--allowedTools` followed by
  the empty string (fails before the change: the flag is absent).
- **TC2 —** the rest of the command is unchanged: `-p` with the prompt, the settings file,
  the empty strict MCP config, the model flag when a model is named.

## Approach

Add `"--allowedTools", ""` to the command in `run_claude`, mirroring `inbox.py:450`. No
caller needs an exception, so no parameter is added — a future stage that genuinely needs a
tool must say so loudly rather than inherit everything by default.
