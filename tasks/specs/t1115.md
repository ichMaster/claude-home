# t1115 — the documents and three tests had fallen behind the code

Found by the full review, 2026-11-01 (truth M11, M12, M13 in
`status/state/code-review/2026-11-01-panel-full-truth.md`).

## Problem

Today the panel gained a login, forms, editors, a permission block and a change-log writer.
The documents describing it were rewritten four times and the **screen descriptions were not**
— the reviewer found twelve lines in `docs/features/ADMIN-PANEL.md` that the code contradicts
and three where the file contradicts itself: "no authentication" beside the phase that added
it, "this screen reads and never writes" above three write paths, features promised and never
built (a *Run* button on Pulse, editors on Zirka and Bruno, *Say this* boxes, drag-to-repin,
*Reindex*, *Remove dead*, *Test on the last 24 h*, the files touched and the suite result
behind each commit, `status/state/runs/`).

Two had a visible consequence rather than only a reading one: the left rail of **every**
screen advertised a «Чат» tab that answers «фаза 9» — the screen t1098 refused and replaced
with «Надіслане» — and `panel/noos-panel.service` still described the panel as "loopback
only, no authentication".

`docs/ROADMAP.md` had v5.7 and v5.8 written as pending after both shipped, named a byte-for-
byte prompt test that does not exist, and counted 30 tests where there are 52. `README.md`
mentioned the panel once, in a list of documents: a reader of the public face could not learn
that there is a long-running service on port 8091 with a password.

And three tests stood in for the wiring they are named after — the shape the phase-8 review
called M2. The worst: `test_the_prompt_is_assembled_in_the_order_start_sh_builds_it` asserts
a list someone typed and never opens `start.sh`, so when `start.sh` gained the permission
block, nothing failed.

## Fix

- The **Screens** section of `ADMIN-PANEL.md` rewritten from the code, screen by screen, with
  the promises that were never built removed rather than left as features. Screen 11 moved out
  of «Technical shape», where it had been pasted, and marked as not built.
- The authentication bullet, the phase statuses (every phase now carries its date), and the
  missing **Phase 9** entry, which was lost when t1098 reworked the chat screen.
- The rail: `/chat` → `/sent`, named «Надіслане», which is what phase 9 actually builds.
- `noos-panel.service`'s header says what is true: the bind, the password, no TLS.
- `ROADMAP.md`: v5.7 and v5.8 marked done with what was actually delivered and what stayed in
  the terminal, the test counts corrected, the byte-for-byte claim replaced by the test that
  now exists.
- `README.md` gains a paragraph on the panel and two lines in the layout.
- A test that reads `start.sh` and derives the prompt's part order from it.

## Test cases

- **TC1 —** the part order is read out of `start.sh`, and the assembled prompt matches it;
  the handoff heading is found in `start.sh` too. (Fails before the fix: the order was typed.)
- **TC2 —** the rail carries no `/chat`, and the unbuilt screen is «Надіслане».
