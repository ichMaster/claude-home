# t1248 — the panel must not retarget secret-file and audit-path config keys

## Problem / goal

`NO_EDIT_PREFIXES` in `panel/rules_screen.py` protects the panel's own settings and
permissions, but not the **path-valued** keys: `telegram.env`, `voice.env`,
`changelog.dir`, `paths.*` (including the interpreter every timer runs),
`probes.auth.credentials`, `probes.auth.fallback_file`, `probes.youtube.oauth_env`.
A single authenticated `POST /rules` with `key=telegram.env value=<file the attacker
can write>` makes `inbox.py` read bot tokens from an attacker-controlled file (and
`save_reference()` gives an authenticated user a writable KEY=value file under
`status/state/`); `key=changelog.dir value=/tmp/x` silently moves all future audit
appends out of the `chattr +a`-protected directory. Both bypass stated hard rules
(«tokens from the terminal only», «changelog is append-only») with one form post.
(Nightly review 2026-11-23, Medium, verified: neither key is masked nor in
NO_EDIT_PREFIXES, and set_setting accepts both.)

## Test cases

- **TC1 (regression) —** `set_setting("telegram.env", …)`,
  `set_setting("changelog.dir", …)` and `set_setting("paths.python", …)` are all
  refused with the protection message and write nothing. Fails before the change.
- **TC2 —** an ordinary scalar key (e.g. `digest.news_memory_days`) is still
  editable — the new prefixes must not over-match.

## Approach

Extend `NO_EDIT_PREFIXES` with the keys whose value names a file the system reads
secrets from, writes audit to, or executes: `paths`, `telegram.env`, `voice.env`,
`changelog.dir`, `probes.auth.credentials`, `probes.auth.fallback_file`,
`probes.youtube.oauth_env`. `reset_setting` shares the same list, so both verbs are
covered. Changing these stays a terminal-only act, like permissions.
