# t1171 — save_claims writes forecast-claims.jsonl atomically

## Problem / goal

`save_claims()` in `status/mood.py` rebuilds the whole claims history in memory and writes it
back with `Path.write_text`, which truncates the file in place before writing. A kill between
the truncation and the completion (systemd timeout, OOM, Ctrl-C during a manual run or
`--resume`) loses every past day's claims — including the `verified` answers that
`mood_feedback.score()` aggregates over 14 days — or leaves a torn partial file. The repo
already has `noosconf.atomic_write_text` for exactly this.

Found by the nightly code review of 2026-11-13 (Medium, confirmed adversarially). v1 is off
the timers since 2026-11-12, but manual runs and `--resume` still hit this path.

## Test cases

- **TC1 —** given a stored day of claims, a write of the next day that is interrupted midway
  (simulated by a torn `Path.write_text`) must not lose the earlier day (regression — fails
  before the fix because the in-place truncate destroys the history).
- **TC2 —** the existing storage tests (replace-per-day, per-subject, other-day untouched)
  keep passing.

## Approach

Replace `f.write_text(...)` with `atomic_write_text(f, ...)`. The read-modify-write lock
(concurrent writers) is noted but out of scope — the morning pipeline is single-run and the
window is milliseconds; a lock belongs to a broader design pass, not a 5am patch.
