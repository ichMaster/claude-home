# t1254 — mood2 pick-stage flake degrades instead of aborting the morning

## Problem / goal

With the configured stages (read, pick, wide, day) the day stage is built entirely from
`items` — ВИБРАНЕ=items_text(items), НАГОЛОС=accent_ids(items), ГОЛОСНІ/ТИСК=pressure(items),
ПЕРІОД from the wide stage — and `chosen` from the pick stage is only logged
(`out["pick"]`); `day.md` carries no `{{ПОПЕРЕДНЄ}}` and `check_reading` is called with
chosen_ids=None. Yet a single pick failure — a timeout (`StageFailed`) or an answer
`json_answer` cannot parse (`Unfaithful`) — propagates out of `run()` and the morning
reading is never produced: exit 3, only the failure notice goes out.

This is the same asymmetry t1251 fixed for the wide stage, with the same rationale: a
supplementary stage must read as degraded output, never a lost morning. Pick is strictly
more supplementary — zero downstream consumers — but still fatal.

## Test cases

- **TC1 —** given the pick stage raising `StageFailed`, `run()` still returns a reading
  (`"day" in out`) and notes the degradation (regression: raises before the fix).
- **TC2 —** same with `Unfaithful` (a non-JSON answer).
- **TC3 — edge:** a healthy pick still lands in `out["pick"]` (covered by the existing
  pipeline tests, which stay green).

## Approach

Wrap the pick stage body in the same `try/except (StageFailed, Unfaithful)` the wide
stage got in t1251: note the error, continue with `selection({}, items)` — the empty
answer path selection() already handles, which restores the mandatory positions and
loses nothing the day stage uses.
