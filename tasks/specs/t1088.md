# t1088 — a numeric dd.mm due date never rolls into the next year

## Problem / goal

Nightly review 2026-11-01. In `tasks/store.py parse_due()` the month-name branch rolls the
year forward when the date has already passed (`до 15 січня` on 2026-11-01 → 2027-01-15),
but the numeric branch four lines below does not: `до 15.01` on the same day →
**2026**-01-15 — a task born 290 days overdue, warning in the tasks probe every day. Any
`/task` sent in November–December with an early-year numeric date gets a past deadline.

## Test cases

- **TC1 —** with today frozen at 2026-11-01, `parse_due("звіт до 15.01")` →
  2027-01-15 (regression — fails before the change with 2026-01-15).
- **TC2 —** an explicit year is never touched: `parse_due("звіт до 15.01.2026")` →
  2026-01-15 even though it is past.
- **TC3 — edge:** a numeric date still ahead this year stays this year:
  `parse_due("звіт до 15.12")` on 2026-11-01 → 2026-12-15.

## Approach

Mirror the month-name branch: when no explicit year was given and `(mo, d)` is earlier than
`(today.month, today.day)`, add one year. The t1048 impossible-date guard is unaffected —
the rollover happens before the `date()` construction and changes nothing for invalid
combinations.
