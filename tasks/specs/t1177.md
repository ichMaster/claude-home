# t1177 — the check reads everyday words as the names of bodies

## Problem / goal

On 2026-11-13 the morning reading never reached the chat. `noos-mood2.service` exited 3 after
four rewrites, each refused by `check_reading()` with «світила, яких у добі немає: вузли».
The astrologer's day for that date carries the Moon, Lilith and Saturn — no nodes at all, so
the writing stage never invented one. What it did was use the ordinary Ukrainian word «вузол»
(a knot — of tension, of thoughts), and `bodies_named()` matched it as Rahu/Ketu.

The cause is the matching method, not the table: `BODY_STEMS` is tested with `stem in text`,
so any stem that happens to be a substring of an everyday word fires. Three are verifiable
today:

- `вузл` / `вузол` → «вузол напруги», «розв'язати вузол» read as the lunar nodes (t1159 added
  the plural stems and widened this);
- `уран` → «**уран**ці» read as Uranus;
- `лун` → «**лун**ає» read as the Moon.

Each false hit is fatal twice over: it marks an invented body (the reading is rewritten), and
in the other direction it can mark a real body as present when it is not, hiding a genuine
omission.

«вузол» is genuinely ambiguous in a way the others are not — it is both a body's name and a
common noun — so it cannot simply be made stricter: making it strict would bring back the
t1159 failure, where a correct reading saying «вузли» counted as never naming them. The two
directions of the check want different answers, and that asymmetry is the fix.

## Test cases

- **TC1 —** (regression) `bodies_named("вночі вузол напруги не розв'язати")` does not report
  the nodes as *claimed*: a reading whose only «вузол» is the common noun, over a day that
  carries no nodes, passes `check_reading()` with no «світила, яких у добі немає».
- **TC2 —** (regression) `bodies_named("уранці легше")` is empty — not Uranus; and a reading
  saying «уранці» over a day without Uranus passes.
- **TC3 —** (regression) `bodies_named("лунає дзвін")` is empty — not the Moon.
- **TC4 —** t1159 keeps working in the direction it was written for: a day that *does* carry
  the nodes and a reading that says «вузли» / «вузлів» / «вузлами» / «узлы» / «Раху» / «Кету»
  is not reported as having lost them.
- **TC5 —** a genuinely invented body is still caught: a reading naming Юпітер over a day
  without it reports «світила, яких у добі немає: Юпітер».
- **TC6 — edge:** inflected and Russian forms still resolve — Місяця, Місяцем, Венери,
  Венерою, Луна, Марсом, Солнце, Юпитер, Лилит.
- **TC7 — edge:** an unqualified «вузол» over a day that *does* carry the nodes still counts
  as naming them (the asymmetry: ambiguous evidence may acquit, never convict).

## Approach

Replace substring matching with anchored patterns. `BODY_PATTERNS` holds one regex per body,
built from the stem plus the endings that actually occur, with `\b` at both ends — so «уранці»
and «лунає» no longer match while «Урана» and «Луны» still do.

The nodes keep both spellings but split by direction:

- `bodies_named(text)` — wide. Any node word, qualified or not. Used for «what did the reading
  mention», i.e. the lost-bodies count.
- `bodies_claimed(text)` — strict. «Раху», «Кету», Russian «узел/узлы», or «вузол/вузли» with
  an astrological qualifier («місячні», «висхідний», «низхідний», «кармічні»). Used for «what
  did the reading invent».

Every other body is identical in both, so only the ambiguous word gets the softer treatment.

Out of scope: whether a failed check should send the reading anyway (asked of the owner
separately), and any change to what the writing prompt is told.
