# t1147 — forecast: the spoken rain window must be the one holding the day's peak

## Problem / goal

`_window()` in `status/probes/forecast.py` keeps the FIRST run of slots at or above the
threshold (`best = best or run`), while the probe's severity is computed from the peak
across the whole day (`rain_peak = max(...)`). Given light morning rain (55% at 6:00) and a
heavy evening downpour (90% at 18:00–21:00) — a routine wttr.in day — the spoken text says
«Дощ з 6:00 до 9:00, ймовірність до 55 відсотків» while `severity=warn` and
`value.rain_chance=90` come from the evening rain the text never mentions. The listener
plans a dry evening; the warn's cause is absent from the message.

Found by the nightly code review of 2026-11-11 (M2), confirmed by execution.

## Test cases

- **TC1 (regression) —** given hourly slots with chanceofrain 55 in the morning and 90 in
  the evening, the precipitation line names the evening window and its 90% peak, matching
  `value.rain_chance` and the warn severity. Fails before the change (names 6:00–9:00 at
  55%), passes after.
- **TC2 —** a single rain window behaves exactly as before (the stored Lviv fixture's
  output is unchanged — existing tests guard this).
- **TC3 — edge:** two runs with equal peaks — the earlier one is spoken (ties keep the
  first, `max` is stable).

## Approach

`_window()` collects every run and returns the one with the highest peak instead of the
first; ties go to the earliest run. The line format and all wording stay untouched (the
owner tuned them). Deliberately out of scope: speaking more than one window per
precipitation type — one line per type is the tuned shape; the weaker window loses its
mention, which is the lesser omission since severity, `rain_chance` and the spoken peak now
agree.
