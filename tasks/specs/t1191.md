# t1191 — youtube archive rewritten non-atomically, torn by a power cut

## Problem / goal

Found by the nightly review of 2026-11-16 (adversarially verified). Every probe run with
fresh videos reads the whole 45-day `youtube-archive.jsonl` and rewrites it with
`Path.write_text` — truncate, then write up to 20000 lines. A kill or power cut mid-write
(power outages are routine on this machine; the `loe` probe exists for them) leaves the
archive truncated or empty, and it cannot be rebuilt: RSS feeds hold only ~15 entries per
channel, so Bruno's topic-search history is gone. This is the exact torn-write failure
t1044 fixed on the sibling `youtube.json`; every other write in the same function already
uses `atomic_write_text` — the archive is the one exception. The same raw `write_text`
lives in `status/bots/backfill_youtube.py`, and with three timers plus manual runs as
writers, two overlapping unlocked read-modify-writes also silently drop each other's
records.

## Test cases

- **TC1 (regression)** — the archive write goes through `atomic_write_text` (temp file +
  `os.replace`), never through a bare `write_text`: `update_archive` with a monkeypatched
  recorder writes the archive only via the atomic helper.
- **TC2 (behaviour kept)** — `update_archive` merges fresh entries into the kept records:
  entries older than `archive_days` are dropped, a fresh link already present is not
  duplicated, the result is valid JSONL in the same shape.
- **TC3 (lock)** — the read-modify-write runs under `locked(archive)`, so two overlapping
  writers serialize instead of losing each other's records.

## Approach

Extract the existing archive block from `main()` into `update_archive(archive, fresh)`
unchanged in behaviour, wrap its read-modify-write in `with locked(archive):` and replace
the final `write_text` with `atomic_write_text` (both already in `noosconf`; t1044
precedent). `backfill_youtube.py` gets the same two-line treatment on its final write.
Out of scope: the `--drain` ordering of `pending` против the last-digest copy (a separate
Low finding), and any change to what the archive stores.
