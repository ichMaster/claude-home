# t1109 — the configuration froze at process start

Found by the full review, 2026-11-01 (truth H4 in
`status/state/code-review/2026-11-01-panel-full-truth.md`).

## Problem

`noosconf.DATA = _load()` ran once, at import. That was fine while every reader was a
short-lived script. The panel is not: it lives for weeks, and since t1102 it **writes**
configuration itself. So three screens kept stating the value the file held when the panel
started:

- the Sources toggle reads the channel list through `conf()` and writes `config.local.json`
  directly, so a channel reported «вимкнено» went on showing as enabled — the screen
  contradicting its own success message;
- the Rules permission table and the Prompt screen's permission part read `conf()` too, so a
  permission changed from the terminal stayed invisible until a panel restart.

A security finding (M5 in the security report) rests on the same thing from the other side:
settings that weaken the panel itself only took effect at the next restart, which made them
look harmless when they are not.

## Fix

`conf()` re-reads the files when they change: `_refresh()` stats both configs, at most once
every `FRESH_FOR` (2 s), and reloads only when an mtime or a size differs. `ROOT` is part of
the staleness key, so a tool or a test that repoints it gets its own files immediately. A
file that stops parsing — a torn write mid-save — keeps the last good configuration rather
than blanking a running process. `reload()` forces it for a caller that just wrote.

`tests/conftest.py` gains an autouse fixture that restores the real configuration after every
test, because several tests repoint `ROOT` at a temporary directory and would otherwise leave
the rest of the suite reading it.

## Test cases

- **TC1 —** a value changed on disk is visible to `conf()` without a restart. (Fails before.)
- **TC2 —** a config that stops parsing keeps the last good values.
- **TC3 —** an unchanged file is not re-read: fifty `conf()` calls cause at most one load.
- **TC4 —** the whole suite stays green and order-independent.
