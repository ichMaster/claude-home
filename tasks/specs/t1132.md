# t1132 — five panel writes never reach the change log

## Problem / goal

The panel's hard rule (t1113, CLAUDE.md): «every write it makes is appended to changelog/».
Five write actions violate it:

- `zirka_action` `reference` and `ingest` **return before** the
  `changelog_write.record(...)` whose own membership list names them — the record is dead
  code for exactly those two. A stored astrologer reference (a real write to
  `astro-reference-inbox/` and, via `--learn`, to the rules file) leaves no trace in the
  change log; the Changes screen and the 23:30 daily summary silently omit it.
- `tasks_action` `defer` and `block` run `store.py` writers with no record, while the
  sibling `add`/`done`/`start`/`stop`/`cancel` branches all record.
- `memory_action` `pin_up`/`pin_down` run `facts.py pin` with no record, while
  `add`/`rm` record.

## Test cases

- **TC1 (regression) —** a stored reference leaves a `panel-zirka` record (fails before).
- **TC2 —** an ingested parked file leaves a `panel-zirka` record.
- **TC3 —** `defer` and `block` leave `panel-task` records.
- **TC4 —** `pin_up` leaves a `panel-fact` record.
- **TC5 —** a failed script run records nothing (a refusal changed nothing — t1113's rule).

## Approach

Record inside each branch after the write succeeds: in `save_reference` right after the
inbox file is written (the file is a write even when the follow-up script fails), in the
`ingest`/`defer`/`block`/`pin` branches after `ok`. Drop `ingest`/`reference` from the
membership list at the recalc/ask/calibrate record, which they never reached.
