# t1070 — an ingested reference leaves the inbox

Found by the phase-3 review (92bf21c, t1068), finding M2 in
`status/state/code-review/2026-10-31-panel-phase3-scan.md`.

## Problem / goal

Nothing ever removes a file from `status/state/astro-reference-inbox` after
`astro_learn.py add --file` has appended it to the store. Two concrete failures on the
Zirka screen (t1068):

1. Pasting a reference succeeds — and the page immediately lists the same text under
   «Чекають на внесення (з чату Зірки)» with an «внести» button, because `save_reference`
   writes the paste into that same inbox. The screen claims a just-ingested reference was
   never ingested; pressing the button appends a duplicate to `astro-reference.jsonl` and
   burns another model call (`--learn` is hardcoded on ingest).
2. A genuinely parked file stays listed forever after «внести»; every further press is
   another duplicate plus another model call. `learn()` reads the newest record, so
   calibration then works from the duplicate.

## Test cases

- **TC1 — regression.** `consume()` moves a file that lives in the inbox into
  `ingested/` beside it and returns the new path; the top-level listing (`*.txt` in the
  inbox) no longer contains it. Fails before the change — the function does not exist.
- **TC2 — foreign files stay.** A file outside the inbox is returned as None and not
  touched: `add --file` on an arbitrary path must not relocate the owner's files.
- **TC3 — edge, name collision.** A file with the same name already in `ingested/` does
  not block the move or get overwritten — the newcomer gets a numbered suffix.
- **TC4 — wiring.** `astro_learn.py add --file <inbox file>` (store pointed at a tmp file)
  records the reference and the file ends up in `ingested/`, raw text intact.

## Approach

The move lives in `astro_learn.py`, not the panel: astro_learn is the one place that knows
the ingest succeeded, and the fix then covers every door — the panel's paste, the panel's
«внести», and the session ingesting by hand after Zirka's chat parked a file. It happens
right after the store write (before `--learn`, which is an extra on top of a completed
ingest). The raw text is kept — losing it was the original complaint (t1059) — it moves to
`ingested/`, which the panel's `parked()` does not glob.

Out of scope: a Post/Redirect/Get for the panel's POSTs (L3 of the scan, Low).
