# t1082 — facts.py rm/pin: path traversal out of the facts directory

Found by the phase-7 review (eeade71, finding H1 in
`status/state/code-review/2026-10-31-panel-phase7-scan.md`). **High.**

## Problem

`facts.py rm <id>` builds `DIR / f"{id}.md"` and unlinks it with no containment check,
and the id arrives from the panel form (`memory_action`, action `rm`). The panel is bound
LAN-wide by design and its form token is readable out of any GET page, so anyone who can
reach port 8091 can POST `action=rm&id=../../../../../home/ich/<anything>` and delete any
`.md` the user can write — `persona.md`, `CLAUDE.md`, the agent memory files under
`~/.claude/projects/**/memory/`, which are in no git repo and outside `versions.files`,
so no version is kept. Demonstrated: `facts.py rm "../../../../../tmp/t1080-check/victim"`
deleted `/tmp/t1080-check/victim.md`, exit 0. The `pin` branch has the same traversal
(rewrites the `pin:` line of an arbitrary `.md`).

## Fix

A helper `fact_file(fid)` resolves `DIR / f"{fid}.md"` and returns it only when its
parent is the facts directory itself; `rm` and `pin` go through it and exit 1 with a
message otherwise. Missing fact → the same clean refusal instead of a traceback.

## Test cases

- **TC1** — `rm` with a `../…` id leaves the target file in place and exits non-zero.
  (Fails before the fix: the file is deleted, exit 0.)
- **TC2** — `pin` with a `../…` id changes nothing and exits non-zero.
- **TC3** — `fact_file` rejects ids with separators and parent-hops; accepts a plain id.
- **TC4** — `rm` of a missing but well-formed id exits non-zero with a message, no
  traceback.
