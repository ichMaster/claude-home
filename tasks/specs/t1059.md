# t1059 — Zirka stops learning from references; calibration comes through the session

## Problem / goal

The owner settled the division of labour (2026-10-31): **the horoscope is calibrated
through the session**, Zirka only explains the reading she already produced and takes his
account of how the day actually went. Learning from another astrologer's forecast moves out
of her chat and into the main one.

Today `inbox.py` does the opposite: a reference pasted to Zirka is classified, stored,
distilled into rules and — since t1033 — triggers a recomputation, all without the session
seeing it. That is three decisions taken in a chat that, by design, has no judgement behind
it: the classifier can mistake a long message about his day for a reference, the author and
the date are guessed, and the rules land in the store before anyone has read them.

## What changes

- A reference arriving in Zirka's chat is **kept, not learned from**: the text is written to
  `status/state/astro-reference-inbox/<timestamp>.txt` and the main chat is told it is
  there. Nothing is distilled, nothing enters `astro-reference.jsonl`. Losing the text was
  the original complaint (three dropped on 2026-10-31), so it is stored before anything
  else happens.
- Zirka answers that references go through the main chat, and stops claiming she learned
  anything.
- **Feedback is unchanged** — his account of a day is exactly what she is for, and it still
  goes to `mood_feedback.py add --source zirka` from the script.
- **Recalculation stays** (t1033). He asked for it explicitly an hour earlier so he would
  not have to reach a terminal, and re-reading a day is not calibration. Said out loud in
  the reply so he can correct it if he meant otherwise.
- `astro_learn.py add --file <path>` is added, so the session can ingest a stored reference
  without passing a few thousand characters through a command line.

## Test cases

- **TC1 (regression)** — a reference in Zirka's chat writes the text to the inbox directory
  and does **not** call `astro_learn.py`; the stored file holds the text verbatim.
- **TC2** — the same reference does not trigger a recomputation: only an explicit `recalc`
  does.
- **TC3** — feedback still reaches `mood_feedback.py add --source zirka`.
- **TC4** — `astro_learn.py add --file` reads the text from a file and stores it under the
  given day, and a missing file exits with an error instead of storing an empty reference.

## Approach

`take_reference()` becomes `park_reference()`: write the file, return the line Zirka says.
The main chat is notified through `notify.sh` the same way a handoff is. The intent prompt
keeps the `reference` kind — recognising one is still useful, it is only the consequence
that changes.

Out of scope: moving the recognition itself into the session. The classifier already runs
there cheaply, and a message that is obviously a reference should not need a round trip to
be filed.
