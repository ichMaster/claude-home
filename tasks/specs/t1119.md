# t1119 — panel: phase 9, the log of what was sent, and the Sent screen

The last phase of the panel. Reworked from the chat screen on 2026-11-01 (t1098) and ordered
by the owner: «роби 9 фазу».

## Problem / goal

**Nothing in this system records what it actually said.** The digest, the forecast, the
reminders, the probe reports and every reply leave through `notify.sh` and are gone. So
«чи сказав дайджест хоч щось о 20:03, чи відпрацював і промовчав» is unanswerable except by
scrolling a phone — and in `systemctl` a timer that ran and said nothing looks exactly like
one that did its job.

## What this builds

**The log.** `notify.sh` appends one line per outgoing message to
`status/state/chat-log.jsonl`: when, which bot, what kind, whether the text and the voice
parts were accepted by Telegram, the length, and the text itself. Two details that make it
truthful rather than decorative:

- the **kind** is the calling script's own name when no `--kind` is given, read from the
  parent process — so a digest says `digest-headless.sh` and a reminder says `remind.py`
  without a single caller having to be changed;
- the **delivery result** is Telegram's HTTP code, not an assumption. A message that failed
  is the whole reason to keep this log.

The chat id is deliberately **not** stored: the bot's name says where it went, and the id is
personal and already lives in one file.

**The screen** (11, `/sent`). Newest first, filter by bot and by kind, and **metadata by
default — not the body**: the text of a digest *is* the owner's calendar and mail. The body
appears only when `panel.sent_bodies` is on. Counters at the top: how many messages today,
how many with voice, how many failed.

**Retention.** The file is trimmed to `sent.max_lines` (5000) on append, newest kept, through
the atomic write — this is a record, not an archive, and the machine has one disk at 91 %.

## Test cases

- **TC1 —** a record carries ts, bot, kind, ok, codes, voice, chars and text; `ok` is false
  when either part's code is not 200.
- **TC2 —** the kind is the `--kind` value when given, and the parent process's name
  otherwise.
- **TC3 —** appending past the cap keeps the newest lines and never loses the one just
  written.
- **TC4 —** a torn line in the log is skipped, not fatal; an absent log is an empty screen,
  not an error.
- **TC5 —** the screen lists newest first, and the filters by bot and by kind work.
- **TC6 —** with `panel.sent_bodies` off, no message body reaches the HTML; with it on, the
  body is there. Everything interpolated is escaped.
- **TC7 —** the counters match the rows: total, with voice, failed.
- **TC8 —** `/sent` leaves `SOON`, and the screen writes nothing.
