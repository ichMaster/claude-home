# t1061 — the probe merged the horoscope and the biorhythms back into one

## Problem

The two readings are kept apart everywhere by design: two model calls, two messages, two
voices, and a biorhythm prompt forbidden to name a planet. The owner set that rule on
2026-10-27 and repeated it on 2026-10-31 — merged into one verdict it stops being visible
which claim came from where.

`status/probes/mood.py` was the one place that undid it. Its `text` was the astrology
summary with the three biorhythm figures appended after a blank line, so `/mood`, the digest
and the watcher all showed one blob with two sources in it — exactly the thing the whole
pipeline is arranged to avoid.

## Test cases

- **TC1 (regression)** — the `mood` probe's text contains the astrology summary and **no**
  biorhythm figures, and its `value` no longer carries them either.
- **TC2** — a new `bio` probe reports the figures and the one-line conclusion, and names no
  planet.
- **TC3** — with a state file from an earlier day, both say the morning has not run rather
  than showing stale content or failing.
- **TC4** — `bio` with figures but no conclusion still reports the figures.

## Approach

Split rather than relabel: `status/probes/bio.py` is its own probe over the same cached
state, and `mood` keeps only the summary. Both are read-only over `astro.state` and call no
model, as before.

`/mood` becomes `send.sh --split mood bio` — two messages, which is what the morning itself
sends and what the split is for. `bio` joins the panel's probe list.

The tests run the probes through `runpy` with `noosconf.path` pointed at a temporary file,
because a probe is a script that works on import and there is no environment override for
the config path.
