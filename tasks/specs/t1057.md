# t1057 — panel: one failed collector must not blank the whole page

Found by the phase-1 panel review (M2 in
`status/state/code-review/2026-10-31-panel-phase1-scan.md`).

## Problem / goal

`panel/data.py` runs three subprocesses with timeouts — `probes_now()` (run.sh, 120 s),
`timer_units()` and `show()` (systemctl, 15 s) — but none catches
`subprocess.TimeoutExpired` or `OSError`. run.sh has no internal timeout and on a cold
cache runs eight probes serially, several fetching the network; a hanging upstream pushes
it past 120 s. The exception escapes `pulse_html()` into the handler's catch-all and the
whole page answers `500 panel error` — the timers, queues and change log that were
perfectly readable go down with the one collector that failed. The module's own docstring
promises the opposite: "a missing value is information, an exception is a blank page".

## Test cases

- **TC1 — regression:** with `subprocess.run` stubbed to raise `TimeoutExpired`,
  `probes_now()` returns `[]` instead of raising. Fails before the change.
- **TC2:** same stub — `timer_units()` returns `[]` and `show()` returns `""`.
- **TC3:** with the stub raising `OSError` (run.sh missing or not executable), all three
  degrade the same way.
- **TC4 — the page survives:** `render_pulse([], [], queues(<empty dir>), [])` still
  contains every section heading, so a dead collector shows its empty-state line while the
  rest of the board renders.

## Approach

Wrap each subprocess call in `try/except (subprocess.TimeoutExpired, OSError)` returning
the collector's empty value. The renderers already have per-section empty states
(«Пробники не відповіли», «Таймерів не знайдено»). Out of scope: retries, partial probe
lists, or an inline error banner — the 500 path stays for genuinely unexpected errors.
