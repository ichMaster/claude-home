# t1081 — facts.py: guard the CLI dispatch with `__main__`

Found by the phase-7 review (eeade71, finding M3 in
`status/state/code-review/2026-10-31-panel-phase7-scan.md`).

## Problem

`memory/facts.py` runs its command dispatch at module level, with no `__main__` guard.
`panel/memory_screen.py::_facts_module` executes the whole file to borrow `load()` — and
with the panel's argv the dispatch falls into the `list` branch, printing **every fact**
(home address, birth data, family) to the panel's stdout, i.e. the systemd journal, on
every GET of `/memory`; a pin POST does it three times. Personal data lands in a log
outside every privacy control the repo has, and grows with page views. Demonstrated by
executing the module with `sys.argv = ["panel/server.py"]`.

## Fix

Move the dispatch into `main()` behind `if __name__ == "__main__":`. The CLI
(`start.sh`, `restart-session.sh`, the panel's `run_script` calls) is unchanged — those
run the file as a script.

## Test cases

- **TC1** — loading the module the way the panel does (`_facts_module`) produces no
  stdout. (Fails before the fix: the fact list is printed.)
- **TC2** — the loaded module still exposes `load()` and `prompt()`.
- **TC3** — the CLI still answers: `facts.py prompt` run as a subprocess prints the
  prompt block (or nothing when no facts), exit 0.
