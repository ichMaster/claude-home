# t1225 — Cyrillic version words (реліз 3.12, версії 2.5) parsed as deadlines

## Problem / goal

The t1215 version guard in `parse_due` (tasks/store.py:125) requires a **Latin** word
before the dotted pair (`[a-z][\w.-]*\s*$`), so a version named in Ukrainian bypasses
it — and the primary input path is voice, transcribed to Cyrillic by Deepgram:

- `зробити реліз 3.12` → due 2026-12-03, title «зробити реліз»
- `оновити до версії 2.5` → due 2027-05-02
- `перейти на пітон 3.12` → due 2026-12-03

The same silent wrong-deadline failure t1215 was committed to close, surviving on the
Cyrillic path. Live proof: adding this very task («fix: Cyrillic version words (реліз
3.12…)») stored due 2026-12-03 with «3.12» cut from the title.

A blanket Cyrillic-word guard would be wrong — «зустріч 20.11» is the normal way to
date a task — so the guard grows by specific version-indicating words only.

## Test cases

- **TC1 —** `parse_due("зробити реліз 3.12")` returns no due date, title intact
  (regression; fails before the fix).
- **TC2 —** `parse_due("оновити до версії 2.5")` and `parse_due("перейти на пітон
  3.12")` return no due date.
- **TC3 — edge:** an ordinary Cyrillic word before a date still parses:
  `parse_due("зустріч 20.12")` returns Dec 20; `parse_due("python 2.7 оновити")` (the
  original t1215 case) still returns no date.

## Approach

Extend the look-behind guard alternation with the version words
`верс\w*|реліз\w*|пітон\w*|пайтон\w*` beside the existing Latin-word branch. Deliberately
narrow: only words that name software versions, never a generic Cyrillic word.
