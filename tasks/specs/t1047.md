# t1047 — mood_feedback.remarks() crashes on a corrupt JSONL line

## Problem / goal

`remarks()` does `json.loads` per line of `mood-feedback.jsonl` with no guard (the sibling
`astro_learn.references` guards exactly this). The file has multiple appenders (the session's
`add`, `inbox.py`'s Zirka feedback) and plain append writes; one torn line — crash or power
cut mid-append — makes every later call raise: `ask` (the 21:00 `noos-mood-ask.timer`),
`list`, `answered_tonight` and `calibrate` all fail until the file is hand-edited.

## Test cases

- **TC1 (regression)** — a feedback file holding one valid line, one truncated line and one
  valid line: `remarks()` returns the two valid remarks instead of raising.
- **TC2** — the same filtering by day still works across the corruption.

## Approach

Skip unparseable lines (try/except `json.JSONDecodeError`), matching
`astro_learn.references`. Nothing else changes.
