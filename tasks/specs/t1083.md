# t1083 — facts.py pin: raw write_text on a precious file

Found by the phase-7 review (eeade71, finding M2 in
`status/state/code-review/2026-10-31-panel-phase7-scan.md`).

## Problem

t1080 declared `memory/facts` precious and rewired `add` and `rm` onto the versioned
atomic path — but `pin` still rewrites the fact file with plain `p.write_text()`: not
atomic (a crash mid-write tears the file) and taking no version (the pre-change text is
unrecoverable). The panel's «вище»/«нижче» buttons go through exactly this path, so the
first screen that lets a button touch a fact also bypasses the safety net built for it.

## Fix

Extract the rewrite into `set_pin(p, level)` that goes through `atomic_write_text` — the
version comes for free, since `memory/facts` is on the precious list. The CLI branch
calls it.

## Test cases

- **TC1** — repinning a fact in a sandboxed precious directory keeps one version holding
  the pre-change content, and the file carries the new pin. (Fails before the fix: no
  `set_pin`, and the raw write keeps nothing.)
- **TC2** — the rewrite changes only the `pin:` line; the fact text survives byte for
  byte.
