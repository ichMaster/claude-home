# t1103 — panel: phase 10b, the file editors and the timer times

Phase 10's second half, and the last of the panel's phases.

## Problem / goal

Two edits are still terminal-only, and both are ones the owner asked for explicitly in the
panel: `persona.md` / `CLAUDE.md`, and the times the timers fire at.

Both are also the most destructive writes in the project. `persona.md` is who I am; a
truncated paste over it is not a bad setting, it is a different assistant. A malformed
`OnCalendar` does not fail loudly — systemd refuses to load the unit, and the timer simply
stops existing until someone notices the digest never came.

## What this builds

**The editors**, on screen 2. A textarea per file, a save, and these guards, each answering
a way I could destroy the file:

- only `persona.md` and `CLAUDE.md`, by name, from a fixed list — never a path from the form;
- an empty or whitespace-only save is refused;
- a save that shrinks the file by more than `panel.edit_min_ratio` (0.5) is refused unless
  the form repeats it with `confirm=1`, so a truncated paste costs one extra click rather
  than the file;
- the write goes through the versioned atomic path, and both files are added to
  `versions.files`, so every save keeps the previous content and `tools/versions.py restore`
  undoes it;
- after a save the restart banner from t1101 says the change is not in force yet, because
  these files are read at launch.

**The timer times**, on screen 8. The `OnCalendar` lines of a timer, editable, with:

- the unit taken from the list systemd itself reported, never from the form;
- every new spec validated with `systemd-analyze calendar` **before** anything is written —
  an invalid spec is refused with systemd's own message;
- the unit file versioned before the write (`~/.config/systemd/user` added to
  `versions.files`);
- `daemon-reload`, then a check that the unit still loads, and **if it does not, the previous
  content is restored and reloaded automatically**. A panel that can break a timer must be
  able to put it back without a human.

Interval timers (`OnUnitActiveSec`) are shown and not editable: four of them exist, none has
an `OnCalendar` line, and rewriting a different directive is a separate decision.

## Test cases

- **TC1 —** saving `persona.md` writes it through the versioned atomic path; the content on
  disk is what was submitted.
- **TC2 —** an empty save, a whitespace-only save, and a file name not on the list are all
  refused with nothing written.
- **TC3 —** a save that halves the file is refused, and the same save with `confirm=1`
  succeeds.
- **TC4 —** `replace_calendar()` replaces every `OnCalendar=` line with the new set, keeps
  the rest of the unit byte-for-byte, and puts the new lines where the old ones were.
- **TC5 —** a unit with no `OnCalendar` is refused rather than rewritten.
- **TC6 —** an invalid spec is refused before the write, carrying systemd's message.
- **TC7 —** a unit systemd did not name is refused and never reaches a command.
- **TC8 —** when the unit fails to load after the write, the previous content is restored and
  `daemon-reload` runs again; the message says so.
