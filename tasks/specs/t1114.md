# t1114 — Pulse and Memory stated things that were not so

Found by the full review, 2026-11-01 (truth M3, M4, M5, M9 and security M6).

## Problems and fixes

- **M3 — an expired pause shown as current.** The YouTube back-off was rendered in amber
  («пауза до 08:44 UTC») forty-four minutes after it had expired. `queues()` now drops a
  pause whose moment has passed; an unreadable stamp stays shown rather than being guessed.
- **M4 — «пошта: останній UID 0» with no state file.** Zero is a fact about the mailbox and
  there was none: the UID is **unknown** until the probe has run, and on this machine
  `.env.gmail` does not exist, so it never has. `mail_last_uid` is `None` and the screen
  says «невідомо (стану ще немає)». The old test asserted the wrong one of those.
- **M5 — «успішно» for a run still in flight.** `Result` holds the *previous* run's verdict
  while the next one is going, so the eight-minute forecast and the digest read as finished
  the moment they started. A row whose service is active now renders «виконується».
- **M9 — the Memory screen showed more than the session is told.** It printed in-prompt facts
  in full while `facts.prompt()` truncates each at `memory.max_fact_chars` (240), so six of
  the 25 were shown longer than the session sees them. Each such fact is now marked with how
  much of it actually reaches the prompt.
- **Security M6 — disclosure rule 1 names one exception and there were two.** The Prompt
  screen says in one line that it shows personal material and that the login is the only
  reason it may; the Memory screen shows the same facts and said nothing. It says it now.
