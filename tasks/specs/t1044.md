# t1044 — youtube probe: lexicographic seen-trim re-reports videos; torn state kills the probe

## Problem / goal

Two defects in `status/probes/youtube.py`:

1. **Seen-set trimmed lexicographically.** `sorted(seen)[-4000:]` keeps the ids that sort
   high, not the ones seen recently. The live state is already at the 4000 cap and its lowest
   kept id starts with "bU" — every id sorting below that (digits, uppercase, `-`, `_`
   prefixes) is evicted regardless of recency. A video seen hours ago whose id sorts low is
   re-detected as "new" on the next window pass and re-sent in a later digest.
2. **State read unguarded, write non-atomic.** `json.loads(STATE.read_text())` with no
   try/except, and plain `write_text` of a ~100 KB file on every run. One kill mid-write and
   every subsequent run (watch, social, the 18:05 drain) crashes with `JSONDecodeError` —
   video collection and the daily digest stop until the file is deleted by hand.

## Test cases

- **TC1 (regression)** — `trim_seen` keeps the most recently seen ids and drops the oldest:
  given 5 ids in insertion order and cap 3, the last 3 inserted survive even when they sort
  lexicographically lowest.
- **TC2 (regression)** — `load_state` on a truncated/corrupt state file returns `{}` instead
  of raising.
- **TC3** — `trim_seen` deduplicates while preserving the latest occurrence's position.

## Approach

Keep `seen` as insertion-ordered (`seen_order` list + set, `mark_seen()`); trim with a new
pure `trim_seen()` keeping the newest `probes.youtube.seen_cap` (4000) entries. Guard the
state read with `load_state()`; write state via `noosconf.atomic_write_text`. Wrap the script
body in `main()` so the helpers are importable by tests without running the probe. The
existing seen list carries no timestamps, so the first trim after this change still starts
from the current (already lexicographic) order — self-corrects within days. Non-atomic
archive/last-digest writes are Low findings, left as reported.
