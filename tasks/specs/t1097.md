# t1097 — panel: a multi-line `.env` value had its body printed as a variable name

Found by the phase-8 review (8c700a3, finding M4).

## Problem

`rules_screen.key_rows` enforces the keys section's one absolute rule line by line — only a
variable's **name** and whether it is non-empty may leave the function — by skipping any line
without `=`. A base64 line carries `=` as padding, so the second line of a PEM or of a
pasted service-account blob becomes a "name" and is rendered on the unauthenticated port.

Demonstrated in the review with a multi-line `GOOGLE_KEY="-----BEGIN PRIVATE KEY-----`:
the key's own body came back as the next variable name.

None of the six configured files is multi-line today, so this is latent — but the likeliest
trigger is already in `panel.key_files`: `.env.youtube` holds Google OAuth material, which
is exactly what people paste as multi-line JSON or PEM.

## Fix

Two parts, because the name pattern alone is not enough: that PEM's base64 line is pure
alphanumerics and matches `^[A-Za-z_][A-Za-z0-9_]*$` perfectly.

- The parser tracks a quote: a value that opens `"` or `'` without closing it on the same
  line swallows the following lines until the closer. They are the value's body — neither a
  variable nor junk — and never printed.
- A name must still match the pattern after the optional `export `. Anything else is counted,
  not printed («N рядків не схожі на змінні»), so a file whose shape we do not understand is
  visible as such rather than silently half-shown.

Also fixed in passing, same function and same invariant (review L2): `FOO=""` reported
«задано», because emptiness was judged before the quotes were stripped. «Задано» is the claim
a reader checks when a probe is warning, so it must mean configured.

## Test cases

- **TC1 —** a file holding a multi-line PEM value yields exactly one variable name, no
  fragment of the key body appears in the row or in the rendered HTML, and the body is not
  counted as junk either. (Fails before the fix: the base64 line is returned as a name.)
- **TC2 —** ordinary shapes still parse: `NAME=value`, `export NAME=value`, a comment, a
  blank line, a value containing `=`.
- **TC3 —** a line that is not a variable is counted, and the count is rendered.
- **TC4 —** `FOO=""` and `FOO=''` read as «порожнє», not «задано».
