# t1196 — a missing reading is announced where the reading lives

## Problem / goal

This morning the 08:15 run stopped — his calendar for the day had not arrived — and said so
through `notify.sh` with no bot argument, which is the **main** chat. The owner waits for the
reading in Zirka's chat, saw nothing there, and asked at 09:50: «Не бачив від Зірки гороскоп
сьогодні». His instruction: «нехай Зірка пише якщо є проблеми замість того щоб мовчати».

The reading has had its own bot and its own voice since the broadcasts were split out. The
notice that there is no reading belongs in the same chat and the same voice — a silent chat is
indistinguishable from a chat whose message was missed.

## Test cases

- **TC1 — regression:** `report_failure` calls `notify.sh` with `--bot mood` and the reading's
  own voice profile. Before the change the command carries neither.
- **TC2 —** with no bot configured for the reading (`telegram.bots.mood` absent) the call
  carries no `--bot`, so a plain setup still gets the notice through the main bot.
- **TC3 —** a broken `notify.sh` still cannot raise: the run's real exit code must survive it.

## Approach

`report_failure` builds its command the way `mood.send` does — `--bot <role>` when a bot is
configured, `--voice-profile` from `astro2.voice_profile`. One message, in her chat, in her
voice; the main chat keeps getting operational failures through the watcher.
