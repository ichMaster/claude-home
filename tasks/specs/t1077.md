# t1077 — a future-dated task belongs in «Період», not «Беклог»

Found by the phase-6 review (04c09b7, finding M5 in
`status/state/code-review/2026-10-31-panel-phase6-scan.md`).

## Problem

`columns()` routes an open task that is neither overdue nor due today into «Період» only
when it carries a period; a task with a hard *future* date falls through to «Беклог». But
the board's own «завтра» button creates exactly that task — press it on a today task and
the card drops into «Беклог», reading as demoted and dateless. The t1074 spec defines
Беклог as "no date and no period", which such a task violates. With t1075 fixed the
inconsistency got louder: «вихідні» moves a task to «Період» while «завтра» buries it in
«Беклог».

## Spec amendment (t1074)

«Період» holds everything scheduled for later — a period *or* a hard future date — sorted
by when it starts. «Беклог» is truly dateless. (The t1074 spec left future dates
unplaced; this is the resolution, chosen so the three defer buttons all move a task into
the same visible place.)

## Test cases

- **TC1** — an open task due tomorrow lands in «Період», not «Беклог». (Fails before.)
- **TC2** — the period column sorts by what starts sooner, mixing dated and period cards
  (due date against period start).
- **TC3** — a malformed one-element period list does not crash the sort (the board
  degrades per-card, never whole-screen) — hardening L2 from the same scan.
