# t1246 — defer with an empty date phrase must refuse, not wipe the deadline

## Problem / goal

The t1048 guard in `tasks/store.py` (`cmd == "defer"`) fires only when
`phrase.strip()` is truthy: `if phrase.strip() and not due and not period`. So
`store.py defer t001` — the date phrase forgotten, or passed as `""` by a caller —
skips the guard, appends `{"op": "defer", "due": null}`, and replay silently wipes
the task's existing deadline. This is exactly the data loss t1048 guarded against,
reachable through the guard's own empty-phrase hole. (Nightly review 2026-11-23,
Medium, verified by simulation.)

## Test cases

- **TC1 (regression) —** given a task with a deadline, when `defer <id>` runs with
  no date phrase, then it exits non-zero and the deadline is unchanged. Fails
  before the change, passes after.
- **TC2 —** `defer <id> завтра` with a parseable phrase still moves the date
  (already covered by `test_defer_valid_date_still_works`).

## Approach

Make the guard fire whenever nothing parsed — drop the `phrase.strip()`
precondition — with a clearer message for the empty-phrase case. An explicit
"remove the deadline" operation, if ever wanted, should be its own verb, not a
silent side effect of a forgotten argument.
