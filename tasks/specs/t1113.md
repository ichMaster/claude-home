# t1113 — the panel's writes now reach the change log, and its standing rules are true again

Found by the full review, 2026-11-01 (truth M1, M2 and M14 in
`status/state/code-review/2026-11-01-panel-full-truth.md`).

## Problems

**M2 — the panel claimed every write reached the change log; none did.** The Rules screen
renders it as a standing rule and `docs/features/ADMIN-PANEL.md` states it as the panel's one
hard rule, with the consequence spelled out: "a week later it is still visible who changed
what". `grep changelog panel/*.py` found one occurrence — a read, on the Pulse screen. The
`PostToolUse` hook is a Claude Code hook: it sees the session's tool calls and nothing the
panel does on its own. So every panel edit was invisible.

**M1 — two standing rules on the Rules screen were false as of this morning.** One said the
panel has no authentication and that forms wait for phase 10; both halves stopped being true
with t1100 and t1102/t1103 — the settings table on that same page is a form. The guard test
stayed green because the anchor phrase survived in `panel/server.py` inside a quotation of
the *withdrawn* reasoning. A substring test cannot tell a rule from a quotation of a dead
rule.

**M14 — `CLAUDE.md` had no panel section**, although the panel now writes the files
`CLAUDE.md` governs.

## Fixes

- `panel/changelog_write.py` appends a record with the same six fields the hook writes and
  `session: panel`, and every panel write and action goes through it: a setting saved or
  reset, a file edited, a schedule changed, a fact added or removed, a task touched, a
  channel toggled, a scenario run, a Zirka button pressed. A refusal is not a change and is
  not logged. A failure to log never costs the write — the log is a record, not a gate.
- The two false standing rules are replaced by what is true now, anchored in the new
  `CLAUDE.md` section rather than in a comment that could become a quotation.
- `CLAUDE.md` gains **The admin panel**: the one hard rule, the login and its terminal-only
  password, the bind and the missing TLS, a table of what the panel may and may not write,
  the machine-readable permissions, and the rule that a screen must never state something
  false.

## Test cases

- **TC1 —** a record carries the hook's six fields and `session: panel`.
- **TC2 —** the log is only appended to.
- **TC3 —** an unwritable log does not raise and does not stop the write.
- **TC4 —** a setting save, a reset and a file save each leave a record of their own kind.
- **TC5 —** a refused write leaves none.
- **TC6 —** every standing rule's anchor still exists in the file it cites (the existing
  guard, now pointing at statements that are current).
