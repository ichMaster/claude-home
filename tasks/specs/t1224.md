# t1224 — decimal durations (1.5 дня, 2.5 год) parsed as deadlines

## Problem / goal

The t1216 measure-word guard in `parse_due` (tasks/store.py:129) covers money, weight,
distance and the full time stems `годин/хвилин/секунд`, but omits the duration units
`день/дні/дня/днів`, `тижні`, `місяця`, `року` and the abbreviations `год/хв/сек`. So a
dotted decimal before one of those still reads as DD.MM:

- `відпустка на 1.5 дня` → due 2027-05-01, title «відпустка на дня»
- `бігти 2.5 год` → due 2027-05-02
- `чекати 1.5 місяця` → due 2027-05-01
- `звіт за 2.5 тижні` → due 2027-05-02

A decimal duration is the most natural decimal in task language, especially from voice.
Live proof: adding this very task («fix: decimal durations (1.5 дня…)») stored due
2027-05-01 with «1.5» cut from the title.

## Test cases

- **TC1 —** `parse_due("відпустка на 1.5 дня")` returns no due date and keeps the title
  intact (regression; fails before the fix).
- **TC2 —** `parse_due("бігти 2.5 год")`, `("перерва 1.5 хв")`, `("чекати 1.5 місяця")`,
  `("звіт за 2.5 тижні")`, `("проєкт на 1.5 року")` — all return no due date.
- **TC3 — edge:** a genuine date still parses: `parse_due("зустріч 20.12")` returns
  Dec 20; the existing t1216 cases (`10.5 тис`, `1.5 години`) still pass.

## Approach

Extend the measure-word alternation with the duration stems and short forms:
`дн\w*`, `тиж\w*`, `місяц\w*`, `рок\w*`, `рік`, `год\w*`, `хв\w*`, `сек\w*`
(the broader `год\w*/хв\w*/сек\w*` subsume the existing full stems). Nothing else
changes; the Latin/version guard is a separate task (t1225).
