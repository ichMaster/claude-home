# t1071 — /zirka no longer grows sys.path on every request

Found by the phase-3 review (92bf21c, t1068), finding M3 in
`status/state/code-review/2026-10-31-panel-phase3-scan.md`. The same defect `/changes` was
cured of the same day (t1067, a52c2a8), reintroduced by phase 3.

## Problem / goal

`zirka_html()` runs `sys.path.append(str(HOME / "status"))` unguarded, and it runs per
request — every GET of the screen and every POST re-render. The panel is a 24/7 process:
N page views leave N copies of the same directory on `sys.path`, every later import in the
process scans the longer list, and memory grows without bound.

## Test cases

- **TC1 — regression.** Calling `zirka_html()` twice leaves `sys.path` exactly as it was
  after the first call. Fails before the change — each call appends one more entry.

## Approach

The same guard t1067 gave `changes_html`: append only if the entry is not already there.
