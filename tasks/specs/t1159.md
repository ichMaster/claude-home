# t1159 — mood2 BODY_STEMS cannot match «вузли», its own canonical name for the nodes

## Problem / goal

`BODY_STEMS` maps `кету`, `раху`, `узел`, `вузол` → «вузли», but none of those stems is a
substring of the plural forms «вузли», «вузлів», «вузлами» (the singular «вузол» has «о»
where the plural has none). So on a day carrying a node transit — real: the current reference
span holds a Марс–Кету window for ~10 days — a correct reading that names the nodes as
«вузли» fails `check_reading`'s lost-bodies count («світила доби, яких у читанні немає:
вузли»), and the retry hint asks the model to add the very word the matcher cannot see. After
`retries`+1 attempts the run raises `Unfaithful` and exits 3: no morning reading, caused by a
correct one. Runs so far passed only because the model happened to write «Кету».

Found by the nightly code review, 2026-11-12 (scan report, Medium #2); verified empirically.

## Test cases

- **TC1 —** `bodies_named` resolves «вузли», «вузлів», «вузлами» (and Russian «узлы», which
  the read stage may leave in a meaning) to «вузли» (regression: all return an empty set
  before the fix).
- **TC2 —** the existing forms («Кету», «вузол», «узел») still resolve.

## Approach

Add the stems `вузл` and `узл` to `BODY_STEMS`. The existing singular stems stay (they are
not substrings of each other's forms); everything still maps to the one «вузли» entity.
