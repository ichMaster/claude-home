# t1168 — watch.py wipes its state when run.sh returns nothing

## Problem / goal

`main()` does `probes = json.loads(raw) if raw.strip() else []`. When run.sh fails (its
aggregator dies on one torn cache line, or the process is killed), stdout is empty →
`probes=[]` → the loop never runs → `newstate` stays `{}` → the quiet path saves it. Every
probe's signature and `sent` timestamp is erased: the next 15-minute tick treats every active
warn/alert as "changed" and re-sends it, and the 3-hour alert reminder clock resets. One
transient glitch becomes spurious duplicate alerts and lost "повернулось у норму" tracking.
A malformed (non-JSON) run.sh output would crash the run entirely.

Found by the nightly code review, 2026-11-12 (scan report, Medium #11).

## Test cases

- **TC1 —** given existing watch.json state and run.sh returning empty stdout, when `main()`
  runs, then the state file is left untouched (regression: fails before the fix — the state
  is wiped to `{}`).
- **TC2 —** run.sh returning malformed JSON → same: no crash, state untouched.
- **TC3 —** a normal run with probes still updates state (the guard must not freeze it).

## Approach

Treat empty or unparseable run.sh output as "this run saw nothing": print a line and return
before touching state. An empty probe list is indistinguishable from a failed run.sh (run.sh
always emits one entry per configured probe), so keeping the old state is the safe reading.
