# t1219 — zirka_kind failure falls back to chat, never to feedback

## Problem / goal

When the classification call fails — `call_claude` raising (an expired login, t1187/t1188,
is a documented recurring event; an API 5xx), the answer carrying no JSON, or the JSON not
parsing — `zirka_kind` returns `{"kind": "feedback"}` (status/bots/inbox.py:327-347). The
caller then runs `record_feedback(text)`: any Zirka message of 25+ characters is appended
to `mood-feedback.jsonl` as calibration data while the classifier is down. The function's
own docstring states the stake: «Misreading a reading as feedback would poison the
calibration» — a forwarded astrologer's reading, arriving exactly when the model is
unavailable, is recorded as the owner's account of his day. An unknown `kind` from a
successful call is coerced to `feedback` too (line 345-346), same poison.

`chat` is the safe floor: the message is still answered; nothing is recorded. A lost remark
costs one data point; a poisoned one costs the calibration.

## Test cases

- **TC1 —** given `call_claude` raises, when `zirka_kind` runs, then it returns kind `chat`
  (regression — fails before the change).
- **TC2 —** given the model answers prose with no JSON, then kind `chat`.
- **TC3 —** given the model answers JSON with an unknown kind, then kind `chat`.
- **TC4 — edge:** a genuine `{"kind": "feedback"}` answer still comes through as feedback.

## Approach

Change the four fallbacks in `zirka_kind` from `feedback` to `chat`. Nothing else: the
prompt and the genuine classification paths stay as they are.
