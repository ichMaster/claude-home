# t1218 — a document refused for size or type says so instead of silence

## Problem / goal

`read_document`'s deliberate refusals — the size cap (status/bots/inbox.py:207-208), a
certainly-binary mime (:214-215), and bytes that turn out not to be text — all return `""`.
`handle_update` then takes `if body:` as «no document text»: under a caption («це на
завтра») the bot answers from three words of caption as if the body never existed, and with
no caption the drop logs the generic «без тексту». No notice is sent either way, unlike the
voice path (t1185) and the transient-failure path (t1213/t1217). A reference forwarded as a
PDF or an oversized paste is silently lost — the exact «a drop has to say what it dropped»
rule of t1054.

## Test cases

- **TC1 —** given an oversized document under a caption, when `handle_update` runs, then a
  notice naming the size refusal is sent, `answer()` never runs, and the drop is logged with
  its reason (regression — fails before the change).
- **TC2 —** given a PDF (binary mime), then `read_document` raises a refusal carrying a
  user-facing notice, with no download attempted.
- **TC3 —** given binary bytes under a `.txt` name, then the same refusal is raised after
  the download.
- **TC4 — edge:** a readable document still flows: text comes back, no notice.

## Approach

A dedicated `DocumentRefused(Exception)` with a `.notice` field, raised by the three
deliberate-refusal branches; `handle_update` catches it before the generic t1213 guard,
logs «документ відхилено: <reason>» and sends the notice. Transient failures (t1217) keep
the generic «не прочитався — надішли ще раз» path.
