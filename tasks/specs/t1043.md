# t1043 — non-atomic rewrite of config.local.json can destroy the personal config

## Problem / goal

`status/tools/youtube_subs.py:append_channels()` and `status/tools/import_youtube_subs.py`
rewrite `config.local.json` with a plain `write_text` (truncate, then write). A kill or power
cut mid-write (`noos-subs.timer` runs daily at 07:50, and the box lives with scheduled
outages) leaves the file truncated. `config.local.json` is git-ignored — no copy in history —
and holds birth data, the calendar id, voices and the 600-channel list; a torn write breaks
`noosconf` and with it every probe, timer and script until manual repair.

## Test cases

- **TC1 (regression)** — given a valid `config.local.json`, when the write fails midway
  (simulated torn write), then the original file still parses as JSON (the failure hits a
  temp file, never the target).
- **TC2** — a successful `append_channels` keeps the file's mode (600) and merges the new
  channel without losing existing keys.
- **TC3** — `noosconf.atomic_write_text` replaces content atomically and preserves the
  target's permissions.

## Approach

Add `atomic_write_text()` to `noosconf.py` (temp file in the same directory, copy the
target's mode, `os.replace`) and use it at both write sites. Other non-atomic state writes
found by the review are fixed under their own tasks; Low-severity ones stay as reported.
