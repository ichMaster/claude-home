# t1180 — cal treats VALUE=DATE-TIME as all-day and kills the whole calendar

## Problem / goal

`parse_dt` decides all-day with `"VALUE=DATE" in params` — a substring test that also
matches `VALUE=DATE-TIME`, which RFC 5545 allows a producer to write explicitly (Google
never does; other feeds do, and `.env.calendar` accepts any iCal URL). Such a DTSTART takes
the all-day branch, `strptime('20261118T100000', '%Y%m%d')` raises ValueError, nothing
guards the event, and the per-calendar except in `main()` marks the entire calendar
«не прочитано» — one valid event drops every event in that calendar.

## Test cases

- **TC1 — regression:** `DTSTART;VALUE=DATE-TIME;TZID=Europe/Kyiv:20261118T100000` parses
  as a timed event at 10:00 local, not all-day, and `events()` lists it (fails before:
  ValueError).
- **TC2:** a real all-day `DTSTART;VALUE=DATE:20261118` still parses as all-day.

## Approach

Match the token, not the substring: `re.search(r"VALUE=DATE(?!-)", params)`. The 8-digit
value fallback stays. Out of scope: a per-event guard around the whole parse (a different,
broader change; the demonstrated failure is cured here).
